# 🔥 스트릭 API

> 🆕 **통합 API v3.8 반영**: `POST /streak/shields/use`를 추가합니다. 사용자가 복구 가능 상태에서 불꽃 방패를 수동 사용해 직전 결석일을 보호할 수 있습니다.
> 

> 🆕 **통합 API v3.7 반영**: 스트릭 보호권의 사용자 노출명은 **불꽃 방패**입니다. 보호권이 있으면 자정에 자동 소모되어 스트릭을 지키고, 보호권이 없으면 하루 동안 `RECOVERABLE` 상태로 복구 기회를 제공합니다.
> 

> 🆕 **통합 API v2.0 반영**: 스트릭은 세트 개수와 무관하게 날짜 기준으로 유지합니다. 오늘 일반 모드로 통과한 학습 세트가 1개 이상이면 스트릭이 유지되며, 복습/실패 제출은 제외합니다.
> 

> ⚠️ **범위 안내**: `GET /streak`는 MVP 범위에 포함하지만, **공동 스트릭 파트너 연결/해제 API는 Post-MVP 후보**입니다.
> 

> 🆕 **톱니바퀴 반영**: 불꽃 방패는 기존 레벨업 보상 외에 `POST /streak/shields/purchase`로 톱니바퀴를 사용해 구매할 수 있습니다.
> 

> ⚠️ 보호권 보유 수의 source of truth는 `child_profiles.shield_count`입니다. `streak_records.shield_count`는 현재 구매/사용/조회 플로우의 정본 컬럼으로 사용하지 않습니다.
> 

## GET /streak

> 스트릭 현황 + 공동 스트릭 파트너 정보 조회
> 

**담당**: BE (문한일) | **인증**: CHILD

**Response 200**

```json
{
  "success": true,
  "data": {
    "continuousDays": 5,
    "lastCompletedDate": "2026-03-28",
    "todaySetCount": 1,
    "shieldCount": 2,
    "status": "ACTIVE",
    "recoveryAvailable": false,
    "recoveryDeadlineDate": null,
    "lastShieldUsedDate": null,
    "partner": {
      "childId": "uuid",
      "nickname": "지우",
      "todayCompleted": true
    }
  }
}
```

> **v1.6**: 파트너 없으면 `"partner": null` 반환
> 

**응답 규칙**

```jsx
- lastCompletedDate != today(KST) 이면 → todaySetCount: 0 반환 (저장값 무시)
- 기존 todayMissionCount 필드를 호환 유지할 경우 설명은 "오늘 완료한 학습 세트 수"로 고정
- status 값:
    ACTIVE: 정상 유지 중
    PROTECTED: 직전 결석일을 불꽃 방패로 보호한 상태
    RECOVERABLE: 보호권 없이 결석했지만 recoveryDeadlineDate 안에 학습하면 복구 가능한 상태
    BROKEN: 복구 마감일까지 미완료되어 스트릭이 0으로 확정된 상태
- recoveryAvailable=true 조건:
    status == RECOVERABLE
    AND today(KST) <= recoveryDeadlineDate
- lastShieldUsedDate는 최근 불꽃 방패가 보호한 결석일(KST date). FE는 이 날짜 기준으로 안내 중복 노출을 로컬에서 제어한다.
- partner.todayCompleted = true 조건:
    파트너의 lastCompletedDate == today(KST)
    AND 파트너의 todaySetCount > 0
```

## POST /streak/partner

> 공동 스트릭 파트너 연결 — **Post-MVP 후보**
> 

**담당**: BE (문한일) | **인증**: CHILD

**Request Body**

```json
{ "partnerCode": "719284" }
```

**Response 200**

```json
{
  "success": true,
  "data": { "partner": { "childId": "uuid", "nickname": "지우" } }
}
```

**예외 처리**

| 상황 | HTTP | code | message | 본인 코드 입력 | 400 | BAD_REQUEST | 본인의 코드는 입력할 수 없어요 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 이미 파트너 연결됨 | 409 | CONFLICT | 이미 친구와 연결되어 있어요 | 상대방도 이미 다른 파트너 연결됨 | 409 | CONFLICT | 친구가 이미 다른 친구와 연결되어 있어요 |

**구현 노트**

```jsx
1. partnerCode로 파트너 child 조회 → 없으면 404
2. 트랜잭션 시작
3. 두 child profile row를 항상 같은 순서로 FOR UPDATE  ← deadlock 방지
4. 내가 이미 파트너 연결되어 있는지 재확인 → 있으면 409
5. 상대도 이미 파트너 연결되어 있는지 재확인 → 있으면 409
6. friend_streaks INSERT
7. 커밋
```

## POST /streak/shields/purchase

> 톱니바퀴로 스트릭 보호권을 구매한다.
> 

**담당**: BE (문한일) | **인증**: CHILD

**Request Body**

```json
{ "count": 1 }
```

**Response 200**

```json
{
  "success": true,
  "data": {
    "shieldCount": 3,
    "purchasedCount": 1,
    "unitCost": 30,
    "gearBalance": 70
  }
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| 톱니바퀴 부족 | 409 | GEAR_NOT_ENOUGH | 톱니바퀴가 부족해요 |
| 구매 수량 오류 | 400 | BAD_REQUEST | 구매 수량을 다시 확인해 주세요 |

**구현 노트**

```jsx
1. CHILD JWT 검증 후 childId 추출
2. child_profiles row를 FOR UPDATE로 조회
3. cost = STREAK_SHIELD_COST(30) * count 계산
4. gear >= cost 검증
5. child_profiles.gear -= cost
6. child_profiles.shield_count += count
7. currency_transactions에 STREAK_SHIELD_PURCHASE 기록
8. 응답에 최신 shieldCount, gearBalance 반환
```

## POST /streak/shields/use

> 복구 가능 상태에서 불꽃 방패 1개를 수동 사용해 직전 결석일을 보호한다.
> 

**담당**: BE (문한일) \| **인증**: CHILD

> ⚠️ 자동 사용은 자정 스케줄러가 처리합니다. 이 API는 `RECOVERABLE` 상태에서 사용자가 직접 복구를 선택하는 수동 사용 경로입니다.
> 

**Request Body**

```json
{}
```

**Response 200**

```json
{
  "success": true,
  "data": {
    "shieldCount": 1,
    "status": "PROTECTED",
    "continuousDays": 5,
    "lastShieldUsedDate": "2026-05-26",
    "recoveryAvailable": false,
    "recoveryDeadlineDate": null
  }
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| 불꽃 방패 없음 | 409 | SHIELD_NOT_ENOUGH | 사용할 불꽃 방패가 없어요 |
| 복구 가능 상태가 아님 | 409 | STREAK_NOT_RECOVERABLE | 지금은 불꽃 방패를 사용할 수 없어요 |
| 복구 기한 만료 | 409 | RECOVERY_EXPIRED | 복구 가능한 시간이 지났어요 |

**구현 노트**

```jsx
1. CHILD JWT 검증 후 childId 추출
2. streak_records와 child_profiles row를 같은 트랜잭션에서 FOR UPDATE로 조회
3. streak.status == RECOVERABLE 검증
4. today(KST) <= recovery_deadline_date 검증
5. child_profiles.shield_count > 0 검증
6. child_profiles.shield_count -= 1
7. streak.status = PROTECTED
8. streak.last_shield_used_date = recovery_deadline_date.minusDays(1)
9. streak.recovery_deadline_date = null, recovery_base_days = null
10. currency_transactions 또는 shield usage log에 STREAK_SHIELD_USE 기록
11. 응답에 최신 shieldCount와 streak 상태 반환
```

// streak_records 테이블 (child_id = PK, 1:1 매핑)
@Entity @Table(name = "streak_records")
public class StreakRecord {
    @Id @Column(name = "child_id")         private UUID childId;
    @Column(name = "continuous_days")      private int continuousDays = 0;
    @Column(name = "last_completed_date")  private LocalDate lastCompletedDate; // KST
    @Column(name = "today_set_count")      private int todaySetCount = 0;
    // 하위 호환이 필요하면 DB 컬럼은 today_mission_count를 유지하되 의미를 today_set_count로 정의
    @Column(name = "status")              private String status = "ACTIVE"; // ACTIVE|PROTECTED|RECOVERABLE|BROKEN
    @Column(name = "recovery_deadline_date") private LocalDate recoveryDeadlineDate;
    @Column(name = "recovery_base_days")  private Integer recoveryBaseDays;
    @Column(name = "last_shield_used_date") private LocalDate lastShieldUsedDate;
}

// child_profiles 추가 필드

### GET /streak — 조회 로직

```java
public StreakResponse getStreak(UUID childId) {
    StreakRecord streak = streakRepo.findById(childId).orElseThrow();
    ChildProfile profile = profileRepo.findById(childId).orElseThrow();
    LocalDate today = LocalDate.now(ZoneId.of("Asia/Seoul"));

    // 핵심: lastCompletedDate != today 이면 저장값 무시하고 0 반환
    int todayCount = today.equals(streak.getLastCompletedDate())
        ? streak.getTodaySetCount() : 0;

    // 파트너 없으면 null 반환 (빈 객체 아님!)
    PartnerDto partner = friendStreakRepo.findByChildId(childId)
        .map(fs -> buildPartnerDto(fs.getPartnerId(), today))
        .orElse(null);

    return new StreakResponse(streak.getContinuousDays(),
        streak.getLastCompletedDate(), todayCount,
        profile.getShieldCount(), partner);
}
```

### StreakService.checkIn() — MissionService.submit() 후 호출

```java
/**
 * 학습 세트 submit 통과 후 호출. 스트릭 증가 + 마일스톤 보상 연동.
 * 반드시 같은 트랜잭션 내에서 실행되어야 함.
 */
@Transactional
public List<RewardDto> checkIn(UUID childId) {
    StreakRecord streak = streakRepo.findByIdWithLock(childId).orElseThrow();
    LocalDate today = LocalDate.now(ZoneId.of("Asia/Seoul"));
    List<RewardDto> rewards = new ArrayList<>();

    if (today.equals(streak.getLastCompletedDate())) {
        // 오늘 이미 체크인 — 진행도만 증가
        streak.setTodaySetCount(streak.getTodaySetCount() + 1);
    } else {
        // 날짜 점프 판단
        boolean consecutive = today.minusDays(1).equals(streak.getLastCompletedDate());
        streak.setContinuousDays(consecutive ? streak.getContinuousDays() + 1 : 1);
        streak.setLastCompletedDate(today);
        streak.setTodaySetCount(1);

        // 마일스톤 보상 (7일: RARE, 30일: EPIC)
        int days = streak.getContinuousDays();
        if (days == 7 || days == 30) {
            TicketType type = days == 7 ? TicketType.RARE : TicketType.EPIC;
            ticketRepo.save(new Ticket(childId, type));
            rewards.add(new RewardDto("TICKET", type.name(), 1,
                "STREAK_MILESTONE_" + days + "D"));
        }
    }
    return rewards;
}
```

### 자정 KST 스트릭 보호/복구 스케줄러

```java
// @EnableScheduling 활성화 필수!
@Scheduled(cron = "0 5 0 * * *", zone = "Asia/Seoul")
@Transactional
public void processStreakReset() {
    LocalDate today = LocalDate.now(ZoneId.of("Asia/Seoul"));
    LocalDate yesterday = today.minusDays(1);

    // 1) 이미 복구 가능 상태였는데 마감일까지 학습하지 않은 경우 확정 초기화
    for (StreakRecord s : streakRepo.findExpiredRecoverableStreaks(today)) {
        s.breakStreak(); // continuousDays=0, todaySetCount=0, status=BROKEN
    }

    // 2) 어제 학습하지 않은 활성 스트릭 처리
    List<StreakRecord> missed = streakRepo.findMissedChildren(yesterday);
    for (StreakRecord s : missed) {
        ChildProfile p = profileRepo.findById(s.getChildId()).orElse(null);
        if (p == null) continue;

        if (p.getShieldCount() > 0) {
            p.setShieldCount(p.getShieldCount() - 1);
            s.markProtectedByShield(yesterday); // status=PROTECTED, lastShieldUsedDate=yesterday, streak 유지
        } else {
            s.markRecoverable(today); // status=RECOVERABLE, recoveryDeadlineDate=today, recoveryBaseDays=continuousDays
        }
    }
}
```

### RECOVERABLE 상태에서 학습 통과 시

```java
public void recordMissionCompletion(LocalDate today) {
    if (status == RECOVERABLE && !today.isAfter(recoveryDeadlineDate)) {
        continuousDays = recoveryBaseDays + 1;
        lastCompletedDate = today;
        todaySetCount = 1;
        status = ACTIVE;
        recoveryDeadlineDate = null;
        recoveryBaseDays = null;
        return;
    }

    // 기존 ACTIVE/PROTECTED 일반 스트릭 증가 로직 수행
}
```

### ⚠️ 구현 주의사항

```jsx
1. todaySetCount 응답 규칙:
   lastCompletedDate != today(KST)이면 반드시 0 반환 (저장값 무시)
   todayMissionCount를 유지하는 경우에도 의미는 오늘 완료한 학습 세트 수로 동일하게 정의

2. partner 없으면 null 반환 (빈 객체 {} 아님)

3. 마일스톤 보상은 streak.continuousDays가 정확히 7 또는 30일 때만
   (30일 이후 60, 90일 추가 마일스톤 구현 시 쉽게 확장 가능)

4. 자정 스케줄러: @EnableScheduling + JVM 타임존 Asia/Seoul 설정 필수
5. 불꽃 방패 자동 사용과 RECOVERABLE 전환은 같은 자정 트랜잭션에서 처리. 보호권이 있으면 항상 보호권을 먼저 사용한다.
6. RECOVERABLE 상태는 다음 KST 하루 안에 일반 학습 세트 통과 시만 복구된다. 복습/실패 제출은 복구 조건에서 제외한다.

5. deadlock 방지: POST /streak/partner에서 두 child_id를 항상
   작은 UUID 순서로 FOR UPDATE 잠금 (min/max 정렬)
```
