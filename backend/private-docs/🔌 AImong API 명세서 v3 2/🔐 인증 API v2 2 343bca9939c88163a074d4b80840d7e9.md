# 🔐 인증 API v2.2

> **버전**: v2.2  \\|  **수정일**: 2026-05-16  \\|  **적용 범위**: 부모/자녀 인증, 세션, FCM 토큰, 계정 생명주기, 다자녀 관리, 알림 설정
> 

> 🆕 **v2.2 반영**: 부모별 자녀 수 제한을 최대 3명으로 정정하고, 부모 로그아웃의 FE/BE 책임 범위를 명시합니다.
> 

> 🆕 **v2.1 반영**: 알림 설정의 실제 FCM gating 기준을 명시합니다. `privacyAlertEnabled`는 개인정보 알림, `studyReminderEnabled`는 학습 리마인더에 적용되며, 가챠 레벨업 FCM은 현재 별도 설정 플래그 없이 부모 FCM 토큰 존재 여부만 확인합니다.
> 

> ⚠️ 부모 로그인은 Firebase Auth에서 처리하므로 서버에는 별도 `POST /parent/login` API를 두지 않습니다. 최초 온보딩은 `POST /parent/register`, 자녀 로그인은 `POST /child/login`으로 처리합니다.
> 

> ⚠️ 현재 AImong은 Supabase Auth가 아니라 Firebase 부모 인증 + 자체 CHILD JWT + Supabase Postgres 구조입니다. Supabase가 앱 JWT를 자동 검증하지 않으므로 Spring Security/JWT Filter에서 인증을 검증합니다.
> 

> ⚠️ MVP에서는 CHILD Refresh Token을 사용하지 않습니다. 자녀 세션은 `sessionToken` 단일 JWT와 `child_profiles.session_version` 비교로 관리합니다.
> 

## POST /parent/register

> 부모 온보딩 — Google 로그인 후 자녀 프로필 생성, 6자리 코드 발급, 스타터 티켓 3장 지급
> 

**담당**: BE (문한일) | **인증**: PARENT (Firebase ID Token)

**Request Headers**

```jsx
Authorization: Bearer {firebase_id_token}
Content-Type: application/json
```

**Request Body**

```json
{ "nickname": "민준" }
```

| 필드 | 타입 | 필수 | 유효성 |
| --- | --- | --- | --- |
| nickname | string | ✅ | 1~20자, 공백만으로 구성 불가 |

**Response 201**

```json
{
  "success": true,
  "data": {
    "childId": "3f1a2b4c-...",
    "nickname": "민준",
    "code": "482917",
    "starterTickets": 3
  },
  "requestId": "req_01HXYZ..."
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| Firebase 토큰 유효하지 않음 | 401 | UNAUTHORIZED | 유효하지 않은 토큰입니다 |
| nickname 누락 또는 빈 문자열 | 400 | BAD_REQUEST | 닉네임을 입력해주세요 |
| nickname 20자 초과 | 400 | BAD_REQUEST | 닉네임은 20자 이하여야 합니다 |
| 코드 생성 충돌 5회 초과 | 500 | INTERNAL_ERROR | 코드 생성에 실패했습니다. 다시 시도해주세요 |

**구현 노트**

```jsx
1. Firebase Admin SDK로 ID Token 검증 → parent_accounts 조회 또는 신규 INSERT
2. 6자리 랜덤 숫자 코드 생성 → child_profiles.code UNIQUE 충돌 시 최대 5회 재시도
3. 트랜잭션 시작
   - child_profiles INSERT (starter_issued = false)
   - tickets INSERT (NORMAL 티켓 row 3개)
   - child_profiles.starter_issued = true
   - streak_records INSERT (child_id)
4. 트랜잭션 커밋
```

## POST /child/login

> 자녀 6자리 코드로 로그인 — 세션 토큰 발급
> 

**담당**: BE (문한일) | **인증**: 없음

> 🆕 **v1.1 변경**: 로그인 실패 제한이 IP 기준 단독에서 **IP + code 기준 병합**으로 변경. JWT payload에 `sessionVersion` 추가.
> 

**Request Body**

```json
{ "code": "482917" }
```

| 필드 | 타입 | 필수 | 유효성 |
| --- | --- | --- | --- |
| code | string | ✅ | 숫자 6자리 정확히 |

**Response 200**

```json
{
  "success": true,
  "data": {
    "childId": "3f1a2b4c-...",
    "nickname": "민준",
    "sessionToken": "eyJhbGci...",
    "profileImageType": "DEFAULT",
    "totalXp": 0
  }
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| code 누락 | 400 | BAD_REQUEST | 코드를 입력해주세요 |
| code가 숫자 6자리 아님 | 400 | BAD_REQUEST | 올바른 형식의 코드를 입력해주세요 |
| 일치하는 코드 없음 | 404 | NOT_FOUND | 코드를 다시 확인해봐요 |
| 30초 잠금 중 요청 | 429 | TOO_MANY_REQUESTS | 잠시 후 다시 시도해주세요 (N초 남음) |

**구현 노트** (v1.8 수정)

```jsx
1. login_attempts 테이블에서 IP, CODE 기준 잠금 상태 확인
   - key 예시: "login:ip:{ip}", "login:code:{code}"
   - 둘 중 하나라도 locked_until > now() 이면 429 반환
   - 3회 연속 실패 시 locked_until = now() + 30 seconds
2. child_profiles.code 조회 → 없으면 IP/CODE 각각 failure_count 증가 후 404
3. JWT 세션 토큰 발급
   - payload: { childId, type: "CHILD", sessionVersion }
   - sessionVersion = child_profiles.session_version
   - exp: 30d
4. 성공 시 login_attempts의 관련 실패 row 삭제 또는 초기화
5. 만료된 row는 조회/갱신 시 무효 처리하고, 주기 cleanup으로 삭제 가능
```

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |

## POST /child/logout

> 자녀 로그아웃 — 현재 CHILD JWT 무효화
> 

**담당**: BE (문한일) \| **인증**: CHILD

> ⚠️ JWT는 stateless이므로 서버에서 토큰 원문을 삭제하지 않습니다. `session_version`을 증가시켜 기존 CHILD JWT를 즉시 무효화합니다. 이 방식은 해당 자녀의 모든 기기 세션을 함께 만료합니다.
> 

**Response 200**

```json
{ "success": true, "data": { "loggedOut": true } }
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| sessionToken 누락/만료/서명 오류 | 401 | UNAUTHORIZED | 로그인이 필요합니다 |
| 자녀 프로필 없음 | 404 | NOT_FOUND | 자녀 프로필을 찾을 수 없습니다 |

**구현 노트**

```jsx
1. CHILD JWT 검증 → childId 추출
2. child_profiles.session_version += 1
3. child_profiles.fcm_token = null 권장 (기기 로그아웃 시 푸시 차단)
4. 이후 기존 JWT는 AuthFilter에서 sessionVersion 불일치로 401 처리
```

## POST /parent/logout

> 부모 로그아웃 — 백엔드는 FCM token을 제거하고, Firebase 로컬 세션 종료는 FE가 담당한다.
> 

**담당**: BE + FE 공동 \\| **인증**: PARENT

**Response 200**

```json
{ "success": true, "data": { "loggedOut": true } }
```

**구현 노트**

```jsx
1. FE가 POST /api/parent/logout 호출
2. BE는 parent_accounts.fcm_token = null 처리
3. FE는 FirebaseAuth.signOut()을 호출해 Firebase 로컬 세션 종료
4. FE는 선택 자녀/앱 캐시 등 로컬 저장소 정리
```

### POST /parent/register — Controller → Service 흐름

```java
// AuthController.java
@RestController
@RequestMapping("/api")
@RequiredArgsConstructor
public class AuthController {
    private final AuthService authService;

    @PostMapping("/parent/register")
    public ResponseEntity<ApiResponse<RegisterResponse>> register(
            @AuthenticationPrincipal ParentPrincipal parent,  // AuthFilter 주입
            @Valid @RequestBody RegisterRequest request) {
        return ResponseEntity.status(201)
            .body(ApiResponse.ok(authService.register(parent.getParentId(), request.getNickname())));
    }
}

// AuthService.java
@Service @Transactional
@RequiredArgsConstructor
public class AuthService {
    private final ParentAccountRepository parentRepo;
    private final ChildProfileRepository childRepo;
    private final TicketRepository ticketRepo;
    private final StreakRecordRepository streakRepo;

    public RegisterResponse register(String parentId, String nickname) {
        // 1. 부모 계정 upsert
        ParentAccount parent = parentRepo.findById(parentId)
            .orElseGet(() -> parentRepo.save(new ParentAccount(parentId)));

        // 2. 6자리 코드 충돌 없이 생성
        String code = generateUniqueCode();

        // 3. 트랜잭션 내 일괄 처리
        ChildProfile child = ChildProfile.builder()
            .parentId(parentId).nickname(nickname).code(code)
            .starterIssued(false).build();
        child = childRepo.save(child);

        // 4. 스타터 티켓 3장 발급 (NORMAL)
        for (int i = 0; i < 3; i++)
            ticketRepo.save(new Ticket(child.getChildId(), TicketType.NORMAL));
        child.setStarterIssued(true);

        // 5. 스트릭 레코드 초기화
        streakRepo.save(new StreakRecord(child.getChildId()));

        return new RegisterResponse(child.getChildId(), nickname, code, 3);
    }

    private String generateUniqueCode() {
        for (int i = 0; i < 5; i++) {     // 최대 5회 재시도
            String code = String.format("%06d", new Random().nextInt(1_000_000));
            if (!childRepo.existsByCode(code)) return code;
        }
        throw new InternalErrorException("코드 생성에 실패했습니다. 다시 시도해주세요");
    }
}
```

```java
public ChildLoginResponse childLogin(String code, String clientIp) {
    // 1. DB 기반 로그인 실패 잠금 확인
    loginAttemptService.validateNotLocked(clientIp, code);

    // 2. 코드 조회
    ChildProfile child = childRepo.findByCode(code)
        .orElseThrow(() -> {
            loginAttemptService.recordFailure(clientIp, code); // 실패 카운트
            return new NotFoundException("자녀 프로필");
        });

    // 3. JWT 생성 — payload: childId, type:CHILD, sessionVersion
    String jwt = jwtProvider.createChildToken(
        child.getChildId(), child.getSessionVersion());

    // 4. 성공 → 실패 카운터 초기화
    loginAttemptService.recordSuccess(clientIp, code);
    child.setLastActiveAt(Instant.now());

    return new ChildLoginResponse(
        child.getChildId(), child.getNickname(), jwt,
        child.getProfileImageType(), child.getTotalXp());
}
```

```java
@Transactional
public RegenerateCodeResponse regenerateCode(String parentId, UUID childId) {
    ChildProfile child = childRepo.findById(childId)
        .orElseThrow(() -> new NotFoundException("자녀 프로필"));

    // 권한 검증 — 본인 자녀가 아니면 403
    if (!child.getParentId().equals(parentId))
        throw new ForbiddenException();

    String newCode = generateUniqueCode();
    child.setCode(newCode);
    child.setSessionVersion(child.getSessionVersion() + 1); // ← 기존 JWT 전부 무효화됨
    // Redis 블랙리스트 작업 없음 (v1.1 이후 삭제)

    return new RegenerateCodeResponse(newCode);
}
```

### JWT Provider 구현 포인트

```java
@Component
public class JwtProvider {
    // application.yml: jwt.secret, jwt.child-expire-days=30

    public String createChildToken(UUID childId, int sessionVersion) {
        return Jwts.builder()
            .claim("childId", childId.toString())
            .claim("type", "CHILD")
            .claim("sessionVersion", sessionVersion) // 검증 시 DB 값과 비교
            .expiration(Date.from(Instant.now().plus(30, ChronoUnit.DAYS)))
            .signWith(secretKey)
            .compact();
    }

    // AuthFilter에서 JWT 검증 후 sessionVersion을 DB 값과 비교
    // DB.session_version != JWT.sessionVersion → 401 반환
}
```

### ⚠️ 구현 주의사항

```
1. @Transactional 범위: register()는 child INSERT + ticket INSERT + starter_issued=true를 
   하나의 트랜잭션으로 묶어야 티켓 발급 실패 시 롤백 가능

2. 코드 UNIQUE 제약: child_profiles.code에 DB UNIQUE INDEX 필수
   (code 충돌은 5회 재시도 후 500)

3. session_version 검증: JWT 토큰의 sessionVersion 값과 DB child_profiles.session_version이

4. FCM 토큰: 등록 실패 시 200을 반환하고 조용히 실패해도 됨 (push 발송 시 재시도)
```
