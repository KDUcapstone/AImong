# 🆕 v1.8 정본 정책 보정

문제 생성 및 출제 운영 기준은 기능 명세서 v3.4, ERD v2.2, 미션/퀴즈 API v2.6과 동일하게 맞춘다.

- 문제은행 운영 풀은 총 1,056문항을 정본으로 둔다. 실제 플레이 세트에 고정 배정되는 문항은 96개 세트 x 10문항 = 960문항이다.
- 각 세트는 고정된 세트 식별자와 난이도 비율 정책을 가진다. 실제 10문항은 요청 시점에 해당 정책에 맞춰 문제은행에서 랜덤 선택한다.
- 서버는 문제 요청 시 고정된 세트 정책을 기준으로 LOW/MEDIUM/HIGH 비율에 맞춰 문항을 런타임 랜덤 선택한다.
- 1,056문항 운영 풀과 소단원당 HIGH 추가 생성 정책은 유지한다. 세트 내부 문항은 정해진 비율에 맞춰 런타임 랜덤 선택한다.
- 품질 검증에서 실패한 문항은 격리 대상으로 관리하되, 일반 출제 시에는 고정 세트 기준을 유지한다.
- 문제 생성 SQL 파일명이나 주석에 1,056 운영 풀 및 런타임 비율 출제 표현이 있는 것은 정상이다. 단, 진행도와 채점 기준은 `setId`로 고정한다.

## 1. 전체 아키텍처

```jsx
[현재 MVP]
교육과정 문서 입력
        ↓
GPT로 문제 초안 생성
        ↓
파싱 / 검증 / 검수
        ↓
question_bank + question_answer_keys 에 사전 적재
        ↓
소단원별 문제은행 구성 완료
  - 16개 소단원(mission)
  - 기존 소단원당 60문항 유지
  - 기존 분포: LOW 30 / MEDIUM 20 / HIGH 10
        ↓
MVP 고정 세트 문제은행 확정
  - 총 96세트
  - 세트당 10문항
  - 실제 플레이 고정 세트: 96세트 x 10문항 = 960문항
  - HIGH 보강 운영 예비 풀: 96문항
  - 전체 운영 풀: 총 1,056문항
  - 세트 식별자와 진행도 기준은 setId로 고정
  - 요청 시점에는 해당 세트의 난이도 비율에 맞춰 10문항을 런타임 랜덤 선택
        ↓
소단원별 별 난이도 세트 구성
  - 별 1개: LOW 7 / MEDIUM 2 / HIGH 1
  - 별 2개: LOW 3 / MEDIUM 5 / HIGH 2
  - 별 3개: LOW 2 / MEDIUM 3 / HIGH 5
  - 별 난이도별 후보 세트 2개씩 구성
        ↓
사용자가 소단원 + 별 난이도 선택
        ↓
[mission_sets 에서 missionCode + starLevel 기준 후보 세트 조회]
        ↓
  미완료 후보 세트 있음?
    ├── YES → 미완료 후보 중 랜덤 1개 선택
    └── NO  → 복습 모드로 전체 후보 중 랜덤 1개 선택
        ↓
[question_bank_safe 에서 set_id 기준 활성 문항 10개 조회]
        ↓
[QuestionServingQualityGuard serving 직전 재검증]
        ├── PASS → 세트 반환 준비
        └── FAIL → 실패 문항 QUARANTINED + 교체 풀에서 대체 문항 탐색
                 └── 반복 실패/문제 부족 → 500 MISSION_SET_NOT_READY 반환
        ↓
[quiz_attempts 생성: quizAttemptId, setId, question_ids_json, expiresAt]
        ↓
총 10문항 세트 반환
        ↓
문제 표시 → check 반복 → submit
        ↓
서버 채점 → 오답 3개 이상이면 실패 / 0~2개면 통과 → XP/보상 지급
```

- 문제 조회의 정본 단위는 `missionId`가 아니라 `setId`입니다.
- 사용자는 소단원 안에서 `별 1개`, `별 2개`, `별 3개` 중 하나를 선택합니다.
- 서버는 선택된 별 난이도에 연결된 후보 세트 중 **미완료 세트를 우선 랜덤 선택**합니다.
- 모든 후보 세트가 완료되어 있으면 복습 모드로 전환하고, 전체 후보 세트 중 랜덤 선택합니다.
- 문제 세트는 항상 **정확히 10문항**이어야 합니다.
- 클라이언트에는 정답과 해설을 내려주지 않고, check/submit 응답에서만 해설을 반환합니다.

### 1-1. 문제 저장 구조 (최신 ERD 기준)

```jsx
Supabase
└── public.missions
    ├── id: UUID
    ├── stage: SMALLINT
    ├── mission_code: VARCHAR(16)   // 예: S0101
    ├── title: TEXT
    └── is_active: BOOLEAN

Supabase
└── public.mission_sets
    ├── set_id: VARCHAR(32)         // 예: S0101-S1-A
    ├── mission_id: UUID
    ├── mission_code: VARCHAR(16)
    ├── star_level: SMALLINT        // 1 | 2 | 3
    ├── variant_no: SMALLINT        // 같은 별 난이도 안의 후보 번호
    ├── title: TEXT
    ├── description: TEXT
    ├── question_count: SMALLINT    // 10 고정
    ├── display_order: INT
    └── is_active: BOOLEAN

Supabase
└── public.question_bank
    ├── id: UUID
    ├── mission_id: UUID
    ├── set_id: VARCHAR(32)         // 실제 플레이 세트에 배정된 경우만 값 존재
    ├── question_type: ENUM         // OX | MULTIPLE | FILL | SITUATION
    ├── prompt: TEXT
    ├── options: JSONB
    ├── content_tags: JSONB
    ├── curriculum_ref: TEXT
    ├── difficulty: ENUM            // LOW | MEDIUM | HIGH
    ├── source_type: ENUM           // STATIC | GPT
    ├── generation_phase: ENUM      // PREGENERATED | RUNTIME
    ├── question_pool_status: ENUM  // ACTIVE | QUARANTINED | RETIRED
    ├── pack_no: SMALLINT           // 기존 생성 묶음 추적용
    ├── created_at: TIMESTAMPTZ
    └── is_active: BOOLEAN

Supabase
└── private.question_answer_keys
    ├── question_id: UUID
    ├── answer_payload: JSONB
    ├── explanation: TEXT
    └── created_at: TIMESTAMPTZ

Supabase
└── public.question_bank_safe
    ├── id
    ├── mission_id
    ├── set_id
    ├── question_type
    ├── prompt
    ├── options
    ├── content_tags
    ├── curriculum_ref
    ├── difficulty
    ├── source_type
    ├── generation_phase
    └── created_at

Supabase
└── quiz_attempts
    ├── id: UUID                    // quizAttemptId
    ├── child_id: UUID
    ├── mission_id: UUID
    ├── set_id: VARCHAR(32)
    ├── question_ids_json: JSONB
    ├── is_review: BOOLEAN
    ├── created_at: TIMESTAMPTZ
    ├── expires_at: TIMESTAMPTZ
    └── submitted_at: TIMESTAMPTZ?
```

- `mission`은 교육 주제/소단원입니다.
- `mission_set`은 실제 플레이 단위입니다.
- `star_level`은 세트의 표시 난이도이고, `question_bank.difficulty`는 문항 자체 난이도입니다.
- 기존 LOW 여유 문항은 삭제하지 않고 교체/복습/품질 격리 대응용 예비 풀로 유지합니다.
- `question_pool_status = QUARANTINED` 또는 `RETIRED`인 문항은 출제 풀에서 제외합니다.

### 1-2. 공통 API 응답 shape

```json
{
  "success": true,
  "data": {
    "setId": "S0101-S1-A",
    "missionId": "uuid",
    "missionCode": "S0101",
    "starLevel": 1,
    "isReview": false,
    "quizAttemptId": "uuid",
    "questionCount": 10,
    "expiresAt": "2026-05-10T10:00:00Z",
    "questions": [
      {
        "id": "q_001",
        "type": "OX",
        "difficulty": "LOW",
        "question": "AI는 항상 정확한 정보를 말한다",
        "options": null
      }
    ]
  }
}
```

- 외부 API 응답 shape는 API 명세서의 `success/data` 래퍼를 따른다.
- `questions[]` 공통 필드는 `id`, `type`, `difficulty`, `question`, `options`입니다.
- `answer`, `answer_payload`, `explanation`은 GET 응답에 포함하지 않습니다.

## 2. 문제 유형별 상세 설계

### TYPE 1: OX

**설명**: 참/거짓을 빠르게 판단하는 개념 확인형 문제. 별 1개와 별 2개 초반 흐름에 적합합니다.

#### 문제 데이터 예시

```json
{
  "id": "q_ox_001",
  "type": "OX",
  "question": "AI가 만든 답을 그대로 숙제로 내면 안 돼요.",
  "answer": true,
  "explanation": "AI는 도움을 주는 도구예요. 하지만 숙제는 내가 이해하고 다시 정리해서 써야 해요.",
  "contentTags": ["SAFETY"]
}
```

#### GPT 생성 프롬프트 예시

```jsx
당신은 초등학생(8~13세)을 위한 AI 리터러시 교육 문제 출제자입니다.

다음 조건에 맞는 OX 문제 1개를 JSON으로 생성해주세요:
- missionCode: {missionCode}
- 별 난이도: {starLevel}
- 문항 난이도: {difficulty}
- 콘텐츠 태그: {contentTags}
- 언어: 쉬운 한국어
- answer는 true 또는 false
- explanation은 2문장 이내

반드시 아래 JSON 형식만 출력:
{
  "type": "OX",
  "question": "...",
  "answer": true,
  "explanation": "..."
}
```

#### 예시 문제

- AI는 항상 맞는 말만 해요. → X
- AI가 알려준 정보는 다시 확인해야 해요. → O
- AI에게 전화번호를 알려줘도 괜찮아요. → X

### TYPE 2: MULTIPLE

**설명**: 보기 중 정답 1개를 고르는 객관식 문제. 별 1개부터 별 3개까지 모두 사용할 수 있는 기본 유형입니다.

#### 문제 데이터 예시

```json
{
  "id": "q_multiple_001",
  "type": "MULTIPLE",
  "question": "AI 답변을 바로 믿기 전에 해야 할 일은 무엇인가요?",
  "options": [
    "그대로 제출한다",
    "다른 자료로 확인한다",
    "친구에게만 물어본다",
    "아무것도 안 한다"
  ],
  "answer": 1,
  "explanation": "AI도 틀릴 수 있어요. 중요한 내용은 책이나 공신력 있는 자료로 다시 확인해야 해요.",
  "contentTags": ["VERIFICATION", "FACT"]
}
```

#### GPT 생성 프롬프트 예시

```jsx
초등학생용 객관식 문제 1개를 JSON으로 생성해주세요:
- missionCode: {missionCode}
- 별 난이도: {starLevel}
- 문항 난이도: {difficulty}
- 콘텐츠 태그: {contentTags}
- 보기 4개
- 정답은 1개만 존재
- explanation은 2문장 이내

반드시 아래 JSON 형식만 출력:
{
  "type": "MULTIPLE",
  "question": "...",
  "options": ["...", "...", "...", "..."],
  "answer": 1,
  "explanation": "..."
}
```

#### 예시 문제

- AI에게 질문할 때 가장 좋은 방법은? → 최대한 자세하게 설명하며 물어본다
- AI와 대화할 때 알려주면 안 되는 정보는? → 집 주소와 전화번호
- AI가 잘못된 정보를 주면 어떻게 해야 할까요? → 다른 자료로 확인한다

### TYPE 3: FILL

**설명**: 문장의 빈칸을 **보기 기반 단어 카드**로 채우는 문제. 자유 주관식이 아니라 제한된 선택지 안에서만 답을 고릅니다.

#### 문제 데이터 예시

```json
{
  "id": "q_fill_001",
  "type": "FILL",
  "question": "AI가 알려준 정보는 항상 ____이 필요해요.",
  "options": ["확인", "복사", "저장", "장난"],
  "answer": [0],
  "explanation": "AI도 실수할 수 있어요. 그래서 중요한 정보는 꼭 다시 확인해야 해요.",
  "contentTags": ["VERIFICATION", "PROMPT"]
}
```

#### GPT 생성 프롬프트 예시

```jsx
빈칸 채우기 문제 1개를 JSON으로 생성해주세요:
- missionCode: {missionCode}
- 별 난이도: {starLevel}
- 문항 난이도: {difficulty}
- 빈칸은 1~2개
- 자유 서술형 금지
- options에는 정답 포함 단어 카드 4~5개 제공
- answer는 정답 카드의 인덱스 배열
- explanation은 2문장 이내

반드시 아래 JSON 형식만 출력:
{
  "type": "FILL",
  "question": "AI가 알려준 정보는 항상 ____이 필요해요.",
  "options": ["확인", "복사", "저장", "장난"],
  "answer": [0],
  "explanation": "..."
}
```

#### 예시 문제

- AI가 알려준 정보는 항상 ____이 필요해요. → 확인
- 좋은 프롬프트는 더 ____하게 쓰는 것이 좋아요. → 구체
- 내 ____는 AI와 대화할 때 알려주면 안 돼요. → 정보

### TYPE 4: SITUATION

**설명**: 짧은 생활 시나리오를 읽고 더 안전하고 적절한 행동을 고르는 상황 판단형 문제. 별 3개 체감 난이도를 만드는 핵심 유형입니다.

#### 문제 데이터 예시

```json
{
  "id": "q_situation_001",
  "type": "SITUATION",
  "question": "친구가 AI에게 숙제를 대신 해달라고 쓰려고 해요. 어떻게 하는 것이 가장 좋을까요?",
  "options": [
    "나도 같이 그대로 답을 복사한다",
    "AI에게 힌트만 받고 직접 다시 써 보자고 말한다",
    "아무 말도 하지 않는다"
  ],
  "answer": 1,
  "explanation": "AI는 생각을 돕는 도구로 쓰는 것이 좋아요. 답을 그대로 복사하기보다 힌트를 받고 직접 정리해야 해요.",
  "contentTags": ["SAFETY", "PROMPT"]
}
```

#### GPT 생성 프롬프트 예시

```jsx
초등학생용 상황 판단 문제 1개를 JSON으로 생성해주세요:
- missionCode: {missionCode}
- 별 난이도: {starLevel}
- 문항 난이도: {difficulty}
- 콘텐츠 태그: {contentTags}
- 짧은 생활 시나리오
- 선택지 2~4개
- 정답은 1개만 존재
- explanation은 2문장 이내

반드시 아래 JSON 형식만 출력:
{
  "type": "SITUATION",
  "question": "...",
  "options": ["...", "...", "..."],
  "answer": 1,
  "explanation": "..."
}
```

#### 예시 문제

- 친구가 AI에 전화번호를 쓰려 해요. 어떻게 해야 할까요?
- AI 답변 두 개가 서로 다를 때 가장 먼저 할 일은 무엇일까요?
- 그림을 부탁할 때 저작권을 생각해야 하는 상황은 어떤 경우일까요?

### 2-5. 콘텐츠 태그 체계

`FACT`와 `PRIVACY`는 더 이상 정식 `question_type`이 아니라, 문제의 학습 주제와 판단 맥락을 표현하는 **콘텐츠 태그**입니다.

#### 권장 콘텐츠 태그

- `FACT`: 팩트체크 / 사실 검증 성격의 문제
- `PRIVACY`: 개인정보 보호 / 노출 방지 성격의 문제
- `PROMPT`: 좋은 질문 만들기 / 프롬프트 작성법
- `SAFETY`: AI 안전 사용 전반
- `VERIFICATION`: 출처 확인 / 비교 / 검증 행동

#### 태그 적용 예시

- `FACT` → 주로 `OX`, `MULTIPLE`, `SITUATION`
- `PRIVACY` → 주로 `SITUATION`, `MULTIPLE`
- `PROMPT` → 주로 `FILL`, `MULTIPLE`, `SITUATION`
- `VERIFICATION` → 주로 `MULTIPLE`, `SITUATION`, `FILL`

> 콘텐츠 태그는 정식 유형과 겹쳐서 부여할 수 있습니다. 예를 들어 하나의 `SITUATION` 문제가 동시에 `PRIVACY`와 `SAFETY` 태그를 가질 수 있습니다.

## 3. 난이도 × 커리큘럼 매핑

| 사용자 표시 난이도 | 세트 구성 | 권장 문제 유형 | 추천 콘텐츠 태그 | 특징 |
| --- | --- | --- | --- | --- |
| 별 1개 | LOW 7 / MEDIUM 2 / HIGH 1 | OX, MULTIPLE, FILL | SAFETY, PRIVACY, FACT | 진입용. 기초 개념과 성공 경험 중심 |
| 별 2개 | LOW 3 / MEDIUM 5 / HIGH 2 | MULTIPLE, FILL, SITUATION | FACT, PRIVACY, PROMPT | 응용 확인. 보통 난이도의 주력 세트 |
| 별 3개 | LOW 2 / MEDIUM 3 / HIGH 5 | MULTIPLE, FILL, SITUATION | FACT, VERIFICATION, PRIVACY, PROMPT | 도전용. 복합 판단과 상황 판단 중심 |
- 별 3개는 HIGH가 많지만, 통과 기준이 8/10이므로 HIGH를 6개 이상으로 고정하지 않습니다.
- 별 3개 HIGH는 `SITUATION`만 반복하지 않도록 가능하면 `HIGH-MULTIPLE`, `HIGH-FILL`도 추가 생성합니다.
- 별 난이도는 외부 표시/선택용이고, 문항 난이도는 `LOW | MEDIUM | HIGH` enum으로 유지합니다.

## 4. 문제 선택 알고리즘 (Spring Boot 서버)

```kotlin
fun selectMissionQuestionSet(
    childId: UUID,
    missionCode: String,
    starLevel: Int
): QuestionSetResponse {
    require(starLevel in 1..3) { "INVALID_STAR_LEVEL" }

    val candidateSets = missionSetRepository
        .findActiveSetsByMissionCodeAndStarLevel(missionCode, starLevel)

    require(candidateSets.isNotEmpty()) { "MISSION_SET_NOT_READY" }

    val completedSetIds = missionSetProgressRepository
        .findCompletedSetIds(childId, candidateSets.map { it.setId })

    val uncompletedSets = candidateSets.filterNot { it.setId in completedSetIds }
    val isReview = uncompletedSets.isEmpty()
    val selectedSet = (if (isReview) candidateSets else uncompletedSets).random()

    val questions = questionBankRepository
        .findActiveQuestionsBySetId(selectedSet.setId)

    require(questions.size == 10) { "MISSION_SET_NOT_READY" }

    val servingValidation = questionServingQualityGuard
        .validateForServing(selectedSet.setId, questions)

    require(servingValidation.validQuestions.size == 10) {
        // 실패 문항은 QUARANTINED 처리하고, 교체 풀에서 대체 가능한 문항을 찾는다.
        "MISSION_SET_NOT_READY"
    }

    val quizAttempt = quizAttemptRepository.create(
        childId = childId,
        missionId = selectedSet.missionId,
        setId = selectedSet.setId,
        questionIds = servingValidation.validQuestions.map { it.id },
        expiresAt = now().plusMinutes(30),
        isReview = isReview
    )

    return QuestionSetResponse(
        setId = selectedSet.setId,
        missionId = selectedSet.missionId,
        missionCode = selectedSet.missionCode,
        starLevel = selectedSet.starLevel,
        isReview = isReview,
        quizAttemptId = quizAttempt.id,
        questionCount = 10,
        expiresAt = quizAttempt.expiresAt,
        questions = servingValidation.validQuestions.map { it.toQuestionResponse() }
    )
}
```

- 조회 기준은 `missionCode`, `starLevel`, `setId`, 현재 사용자의 세션(`quizAttemptId`)입니다.
- 출제 시점에는 `setId`로 고정된 세트 정책을 기준으로 문항을 선택합니다.
- 세트 안의 문항은 사전 고정 배정이 아니라, 해당 세트의 LOW/MEDIUM/HIGH 비율에 맞춰 문제은행에서 10문항을 런타임 랜덤 선택합니다.
- 일반 모드는 미완료 세트 우선 랜덤입니다.
- 모든 후보 세트를 완료한 경우 복습 모드로 전체 후보 중 랜덤 선택합니다.
- 선택된 세트는 serving 직전 재검증을 통과해야 하며, 실패 문항은 `QUARANTINED` 처리합니다.
- 세트 문항이 10개가 아니거나 대체 문항 확보에 실패하면 `MISSION_SET_NOT_READY`를 반환합니다.
- MVP는 선적재 문제은행 기반입니다. 런타임 동적 생성 보충은 feature flag 기반 Post-MVP 경로로만 허용합니다.

## 5. GPT 응답 파싱 및 검증

```kotlin
fun parseAndValidate(gptResponse: String): Question? {
    return try {
        val json = objectMapper.readTree(gptResponse)
        val type = QuestionType.valueOf(json.get("type").asText())

        require(json.has("question"))
        require(json.has("explanation"))
        require(!containsBadWords(json.toString()))
        require(isChildSafe(json))

        when (type) {
            OX -> {
                require(json.has("answer"))
                require(json.get("answer").isBoolean)
            }
            MULTIPLE -> {
                require(json.has("options"))
                require(json.get("options").size() == 4)
                require(json.has("answer"))
                require(hasExactlyOneAnswer(json))
            }
            FILL -> {
                require(json.has("options"))
                require(json.get("options").size() in 4..5)
                require(json.has("answer"))
                require(isSelectableFillFormat(json))
            }
            SITUATION -> {
                require(json.has("options"))
                require(json.get("options").size() in 2..4)
                require(json.has("answer"))
                require(hasExactlyOneAnswer(json))
            }
        }

        json.toQuestion(type)
    } catch (e: Exception) {
        null
    }
}
```

- 검증 기준은 `OX`, `MULTIPLE`, `FILL`, `SITUATION` 4개 타입만 사용합니다.
- `FACT`, `PRIVACY`는 콘텐츠 태그로만 다루며, 전용 파싱 분기는 두지 않습니다.
- 필수 검증 항목:
    - `type`, `question`, `explanation` 존재
    - 타입별 `options` 구조 유효성
    - 정답 1개성
    - 아동 안전성
    - 금칙어 / 부적절 표현 필터
    - 별 난이도와 문항 난이도 간 부조화 여부
- 파싱 또는 검증 실패 시 `null`을 반환합니다.
- 현재 MVP 선적재 파이프라인에서는 검증 실패 문제를 저장하지 않습니다.
- 후속 런타임 보충 단계에서도 검증 실패 문제는 세트에 포함하지 않습니다.
- 재시도는 단순 반복이 아니라 `QuestionGenerationRetryFeedback`이 이전 실패 리포트의 `wordingQualityWeak`, `highDuplicateRisk`, `optionQualityWeak`, `explanationQualityWeak`, `repairHints`를 분석해 다음 생성 프롬프트에 반영하는 적응형 재생성으로 수행합니다.

| 후보 세트 | 별 난이도 | LOW | MEDIUM | HIGH | 용도 |
| --- | --- | --- | --- | --- | --- |

| S0101-S1-B | 별 1개 | 7 | 2 | 1 | 쉬움 후보 2 |

| --- | --- | --- |
| FACT | 16소단원 전반에 고르게 포함 | 사실 검증 / 재확인 학습 |
| PRIVACY | 초중반 소단원 집중 + 전 단계 최소 분산 | 개인정보 보호 중심 |

| VERIFICATION | 별 2개 후반과 별 3개에서 강화 | 출처 확인 / 비교 |
