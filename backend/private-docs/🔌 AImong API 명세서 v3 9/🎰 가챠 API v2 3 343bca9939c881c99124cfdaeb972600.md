# 🎰 가챠 API v2.3

**v2.3 반영**: 조각 보유량은 등급별 잔액이 아니라 자녀별 공통 조각 풀 1개로 통일합니다. `grade`는 교환 대상 펫의 등급과 필요 조각 수를 판단하는 입력값으로만 사용합니다.

**v2.2 반영**: 티켓 종류를 기본 티켓 하나로 통합하고, `ticketType`/`remainingTickets` 계약을 단일 구조로 정리합니다.

**v2.1 반영**: 가챠 레벨업 FCM은 현재 별도 알림 설정 플래그 없이 부모 FCM 토큰 존재 여부만 확인합니다. 설정 대상화가 필요하면 후속 결정으로 `gachaLevelUpEnabled` 같은 별도 플래그를 추가합니다.

**v1.9 반영**: SR 보너스 산식은 `srBonusRaw = srMissCount >= 10 ? (srMissCount - 9) * 0.01 : 0.0`이며, 응답 `srBonus`는 실제 적용치입니다.

## POST /gacha/pull

> 가챠 뛽기 실행 — 난수 생성 반드시 서버에서
> 

**담당**: BE (문한일) | **인증**: CHILD

> 🆕 **v1.1 변경**: `srBonus`는 이제 **실제 적용치(appliedSrBonus)** 기준으로 반환. 오버플로우 방지.
> 

**Request Body**

```json
{ "ticketType": "NORMAL" }
```

| ticketType | 설명 |
| --- | --- |
| NORMAL | 유일한 기본 티켓. 기본 확률표 그대로 사용 |

**Response 200**

```json
{
  "success": true,
  "data": {
    "result": {
      "petId": "uuid",
      "petType": "pet_rare_003",
      "petName": "번개몹",
      "grade": "RARE",
      "isNew": false,
      "fragmentsGot": 3
    },
    "srMissCount": 8,
    "srBonus": 0,
    "levelUp": false,
    "remainingTickets": { "normal": 2 }
  }
}
```

**응답 필드 노트**

- `srBonus`는 실제 적용된 보너스 값(`appliedSrBonus`)이다.
- `petType`은 서버가 관리하는 펫 종류 코드이며 `pet_{grade}_{number}` 형식을 따른다. 예: `pet_normal_005`, `pet_rare_003`
- `petName`은 화면 표시용 이름이며 `petType`과 별도 필드로 반환한다.

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| ticketType 누락 | 400 | BAD_REQUEST | 티켓 종류를 선택해주세요 |
| 해당 티켓 보유량 0장 | 400 | BAD_REQUEST | 티켓이 부족해요! |

**구현 노트** (트랜잭션 전체 처리)

```jsx
트랜잭션 시작

1. tickets row를 FOR UPDATE로 조회
2. 해당 티켓 보유량 확인 → 부족하면 400
3. 티켓 차감
4. child_profiles row를 FOR UPDATE로 조회
5. gacha_pull_count += 1
6. 확률 구간 결정 (gacha_pull_count 기준):
   0~19:  Lv.1 (일밢75% 희귀21% 영웅3.5% 전설0.5%)
   20~49: Lv.2 (일밢66% 희귀24% 영웅7.5% 전설)
   50~99: Lv.3 (일밢56% 희귀27% 영웅13% 전설)
   100+:  Lv.4 (일밢44% 희귀29% 영웅22% 전설)
7. srBonus 계산
   - srBonusRaw = srMissCount >= 10 ? (srMissCount - 9) * 0.01 : 0.0
   - appliedSrBonus = min(srBonusRaw, baseNormalProbability)
   - 응답 srBonus는 appliedSrBonus
   - srBonus는 기본 티켓에 그대로 적용
8. 기본 티켓 확률표 그대로 사용
9. SecureRandom으로 가중 랜덤 등급 결정
10. sr_miss_count 업데이트 (영웅 이상: 0리셋, 그 외: +1)
11. 레벨업 체크 → NORMAL 티켓 row 2개 추가, shield_count += 1, FCM 비동기 발송
    - FCM payload: `type=GACHA_LEVEL_UP`, `gachaPullCount={현재 누적 뽑기 횟수}`
12. 중복 여부 확인 (UNIQUE: child_id, pet_type 기준)
    - 신규: pets INSERT (xp=0, stage=EGG)
    - 중복: 공통 pet_fragments.count += 해당 등급 보상 수 (NORMAL+1, RARE+3, EPIC+8, LEGEND+20)
    - 조각 잔액은 등급별로 나누지 않고 child_id 기준 공통 풀 1개만 유지
13. gacha_pulls INSERT

트랜잭션 커밋
```

**레벨업 FCM payload**

```json
{
  "title": "레벨 업!",
  "body": "자녀의 아이몽이 더 강해졌어요! 함께 축하해주세요",
  "data": {
    "type": "GACHA_LEVEL_UP",
    "gachaPullCount": "20"
  }
}
```

- 가챠 레벨업 FCM은 이벤트당 1회 발송한다.
- 부모 FCM 토큰이 없으면 발송을 스킵한다.
- 현재 `privacyAlertEnabled`, `studyReminderEnabled`, `returnRewardEnabled`, `questRewardEnabled`, `marketingEnabled` 중 어떤 플래그도 가챠 레벨업 FCM을 차단하지 않는다.
- FCM 발송 실패는 `POST /gacha/pull` 응답 성공 여부에 영향을 주지 않는다.

## GET /gacha/fragments

> 조각 보유 현황 조회
> 

> DB 테이블명은 `pet_fragments`, API 응답 필드는 `fragments`로 구분한다.
> 

**담당**: BE (문한일) | **인증**: CHILD

**Response 200**

```json
{
  "success": true,
  "data": {
    "totalCount": 7,
    "fragments": [
      { "grade": "NORMAL",  "count": 7, "exchangeThreshold": 10  },
      { "grade": "RARE",    "count": 7, "exchangeThreshold": 30  },
      { "grade": "EPIC",    "count": 7, "exchangeThreshold": 80  },
      { "grade": "LEGEND",  "count": 7, "exchangeThreshold": 200 }
    ]
  }
}
```

- `totalCount`가 정본 조각 보유량이다. `fragments[].count`는 구버전 FE 호환을 위해 같은 공통 보유량을 반복해 내려줄 수 있으며, 등급별 잔액으로 해석하지 않는다.
- `exchangeThreshold`는 대상 펫 등급별 필요 조각 수다. 조각 자체는 NORMAL/RARE/EPIC/LEGEND로 분리 저장하지 않는다.

## POST /gacha/exchange

> 조각으로 원하는 신규 펫 교환
> 

**담당**: BE (문한일) | **인증**: CHILD

> 🆕 **v1.1 변경**: **이미 보유 중인 펫은 교환 불가**. 신규 펫 획득 전용 API.
> 

**Request Body**

```json
{
  "grade": "NORMAL",
  "petType": "pet_normal_005"
}
```

| 필드 | 타입 | 필수 | 유효성 |
| --- | --- | --- | --- |
| grade | string | ✅ | NORMAL / RARE / EPIC / LEGEND. 조각 잔액 등급이 아니라 교환 대상 펫 등급 |
| petType | string | ✅ | 유효한 펫 종류 코드, grade와 등급 일치 |

**Response 200**

```json
{
  "success": true,
  "data": {
    "petId": "uuid",
    "petType": "pet_normal_005",
    "grade": "NORMAL",
    "stage": "EGG"
  }
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| 조각 부족 | 400 | BAD_REQUEST | 조각이 부족해요! |
| 이미 보유 중인 펫 | 409 | CONFLICT | 이미 보유한 펫이에요 |

**구현 노트**

```jsx
트랜잭션 시작
1. child_id 기준 공통 pet_fragments row FOR UPDATE
2. pet_fragments.count >= 대상 펫 등급의 exchangeThreshold 확인
3. pets UNIQUE(child_id, pet_type) 존재 여부 확인 → 있으면 409
4. pet_fragments.count -= exchangeThreshold
5. pets INSERT { xp=0, stage=EGG }
트랜잭션 커밋
```

```java
// gacha_pulls 테이블 (가챨 이력)
@Entity @Table(name = "gacha_pulls")
public class GachaPull {
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    @Column(name = "pull_id")        private UUID pullId;
    @Column(name = "child_id")       private UUID childId;
    @Column(name = "ticket_type")
    @Enumerated(EnumType.STRING)     private TicketType ticketType;  // NORMAL only
    @Column(name = "result_grade")
    @Enumerated(EnumType.STRING)     private PetGrade resultGrade;   // NORMAL, RARE, EPIC, LEGEND
    @Column(name = "result_pet_type") private String resultPetType;
    @Column(name = "is_new")         private boolean isNew;          // 신규 펫 여부
    @Column(name = "created_at")     private Instant createdAt;
}

// child_profiles에 추가 필드
@Column(name = "gacha_pull_count")   private int gachaPullCount = 0;  // 전체 누적 가챨횟수
@Column(name = "sr_miss_count")      private int srMissCount = 0;     // 스레이다운 비시효돈
```

### POST /gacha/pull — 트랜잭션 전체 로직

```java
@Service @RequiredArgsConstructor
public class GachaService {
    private final ChildProfileRepository profileRepo;
    private final TicketRepository ticketRepo;
    private final PetRepository petRepo;
    private final PetFragmentRepository fragmentRepo;
    private final GachaPullRepository pullRepo;
    private final FcmService fcmService;

    // 중복 펫의 등급에 따라 공통 조각 풀에 더할 보상 수
    private static final Map<PetGrade, Integer> FRAGMENT_REWARDS =
        Map.of(PetGrade.NORMAL, 1, PetGrade.RARE, 3, PetGrade.EPIC, 8, PetGrade.LEGEND, 20);

    // 수준별 확률표 (0~19: Lv1, 20~49: Lv2, 50~99: Lv3, 100+: Lv4)
    private static final double[][] PROB_TABLE = {
        //  NORMAL  RARE    EPIC    LEGEND
        {   0.75,   0.21,   0.035,  0.005 }, // Lv1
        {   0.66,   0.24,   0.075,  0.025 }, // Lv2
        {   0.56,   0.27,   0.13,   0.04  }, // Lv3
        {   0.44,   0.29,   0.22,   0.05  }, // Lv4
    };

    @Transactional
    public GachaPullResponse pull(UUID childId, TicketType ticketType) {
        // 1+4. 티켓 & 프로파일 FOR UPDATE
        ChildProfile profile = profileRepo.findByIdWithLock(childId).orElseThrow();
        Ticket ticket = ticketRepo.findFirstByChildIdAndTypeAndUsedAtIsNull(childId, ticketType)
            .orElseThrow(() -> new BadRequestException("티켓이 부족해요!"));

        // 2. 티켓 차감
        ticket.setUsedAt(Instant.now());

        // 5. gacha_pull_count 증가
        profile.setGachaPullCount(profile.getGachaPullCount() + 1);
        int pullCount = profile.getGachaPullCount();

        // 6. 확률 수준 결정
        int level = pullCount < 20 ? 0 : pullCount < 50 ? 1 : pullCount < 100 ? 2 : 3;
        double[] probs = PROB_TABLE[level].clone();

        // 7. srBonus 계산 & appliedSrBonus 적용
        int srMiss = profile.getSrMissCount();
        double srBonusRaw = srMiss >= 10 ? (srMiss - 9) * 0.01 : 0.0;
        double appliedSrBonus = Math.min(srBonusRaw, probs[0]); // 일반 확률 이상 적용 불가
        probs[0] -= appliedSrBonus;
        probs[2] += appliedSrBonus; // 영웅 확률에 추가

        // 8. 기본 티켓 확률표 그대로 사용

        // 9. SecureRandom 가중 랜덤 등급 결정
        PetGrade grade = weightedRandom(probs);

        // 10. sr_miss_count 업데이트
        if (grade == PetGrade.EPIC || grade == PetGrade.LEGEND)
            profile.setSrMissCount(0);
        else
            profile.setSrMissCount(profile.getSrMissCount() + 1);

        // 11. 레벨업 체크 (pullCount가 수준 경계를 넘었는지)
        boolean levelUp = checkLevelUp(pullCount - 1, pullCount);
        if (levelUp) {
            ticketRepo.save(new Ticket(childId, TicketType.NORMAL)); // normal +1 임시
            ticketRepo.save(new Ticket(childId, TicketType.NORMAL)); // normal +2
            profile.setShieldCount(profile.getShieldCount() + 1);
            fcmService.sendAsync(profile.getFcmToken(), "레벨 업!", "새 레벨에 도달했어요!");
        }

        // 12. 중복 확인 & 펫/조각 처리
        String petType = selectPetType(grade); // 해당 등급에서 랜덤 펫 타입 선택
        boolean isNew = !petRepo.existsByChildIdAndPetType(childId, petType);
        if (isNew) {
            petRepo.save(Pet.builder().childId(childId).petType(petType)
                .grade(grade).stage(PetStage.EGG).xp(0)
                .obtainedAt(Instant.now()).build());
        } else {
            // 중복: 조각 증가
            int fragments = FRAGMENT_REWARDS.get(grade);
            PetFragment frag = fragmentRepo.findByChildIdWithLock(childId)
                .orElseGet(() -> PetFragment.builder().childId(childId).count(0).build());
            frag.setCount(frag.getCount() + fragments);
            fragmentRepo.save(frag);
        }

        // 13. 가챨 이력 저장
        pullRepo.save(GachaPull.builder().childId(childId).ticketType(ticketType)
            .resultGrade(grade).resultPetType(petType).isNew(isNew)
            .createdAt(Instant.now()).build());

        return buildResponse(petType, grade, isNew, pullCount, srMiss, levelUp, childId);
    }

    private PetGrade weightedRandom(double[] probs) {
        double r = new SecureRandom().nextDouble(); // 반드시 SecureRandom!
        double cum = 0;
        PetGrade[] grades = {PetGrade.NORMAL, PetGrade.RARE, PetGrade.EPIC, PetGrade.LEGEND};
        for (int i = 0; i < probs.length; i++) {
            cum += probs[i];
            if (r < cum) return grades[i];
        }
        return PetGrade.NORMAL;
    }
}
```

### POST /gacha/exchange — 조각 교환 로직

```java
@Transactional
public ExchangeResponse exchange(UUID childId, PetGrade grade, String petType) {
    // child_id 기준 공통 조각 FOR UPDATE 로크
    PetFragment frag = fragmentRepo.findByChildIdWithLock(childId)
        .orElseThrow(() -> new BadRequestException("조각이 부족해요!"));

    int threshold = switch (grade) {
        case NORMAL -> 10; case RARE -> 30; case EPIC -> 80; case LEGEND -> 200;
    };
    // threshold는 대상 펫 등급 기준이며, 보유 조각은 모든 등급이 공유하는 공통 count다.
    if (frag.getCount() < threshold)
        throw new BadRequestException("조각이 부족해요!");

    // 중복 확인
    if (petRepo.existsByChildIdAndPetType(childId, petType))
        throw new ConflictException("CONFLICT", "이미 보유한 펫이에요");

    frag.setCount(frag.getCount() - threshold);
    Pet pet = petRepo.save(Pet.builder().childId(childId).petType(petType)
        .grade(grade).stage(PetStage.EGG).xp(0)
        .obtainedAt(Instant.now()).build());

    return new ExchangeResponse(pet.getPetId(), petType, grade, PetStage.EGG);
}
```

```jsx
1. 동시성 제어: pull API는 child_profiles + tickets를 FOR UPDATE로 레코드 로크
   — 동시 요청 시 티켓 중복 차감 방지

2. 난수 생성: Math.random() 금지, SecureRandom 필수
   — 클라이언트에서 난수를 보내면 절대 신뢰하지 말 것

3. srBonus appliedSrBonus 처리:
   srBonusRaw = srMissCount >= 10 ? (srMissCount - 9) * 0.01 : 0.0
   srBonusRaw가 일반 확률(probs[0])보다 클 수 없음
   NORMAL 티켓이 아니면 응답 srBonus는 0.0
   (Math.min(srBonusRaw, probs[0]) 필수)

4. 티켓 관리: used_at IS NULL인 기본 티켓 조회 → 1장 차감
   (tickets 테이블: ticket_id, child_id, ticket_type, used_at)
```
