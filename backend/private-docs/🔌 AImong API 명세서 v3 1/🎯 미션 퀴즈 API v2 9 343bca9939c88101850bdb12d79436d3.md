# 🆕 v2.9 구현 피드백 정합성 보정

- `setId`는 미션 진행도, attempt, check/submit/report 연결을 위한 학습 단위 식별자로 유지한다.
- 실제 문항 선택은 `question_bank.set_id` 고정 10문항 조회가 아니라, `mission_sets`에서 확인한 `missionId + starLevel`을 바탕으로 `question_bank.mission_id + difficulty` 후보 풀에서 수행한다.
- 선택된 10문항은 `quiz_attempts.question_ids_json`에 저장하며, 이후 check/submit/report는 이 attempt 문항 목록을 기준으로 검증한다.
- `check`는 `questionId`가 진행 중 attempt의 `question_ids_json`에 포함되는지 확인하고, 추가로 같은 `missionId`의 활성 문항인지 검증한다.
- 외부 응답의 `score`는 100점 환산 점수로 통일하고, 정답 개수는 `correctCount`로 표현한다.
- `rewards`는 배열이 아니라 `{ gear, exp, fragments }` 객체 구조를 사용한다.
- 예시 ID는 `missionId`, `questionId`, `attemptId`는 UUID, `setId`는 문자열 형식으로 통일한다.

# 🆕 v2.8 어려운 개념어 보강설명(termHints) 구현 계약

- `GET /api/missions/{missionId}/questions`와 `GET /api/mission-sets/{setId}/questions`의 `questions[]`에 `termHints` 배열을 추가한다.
- `termHints`는 정답 힌트가 아니라 용어 뜻 보강이다. 예: `편향` → `한쪽으로 치우쳐서 생각하거나 판단하는 것을 말해요.`
- 용어가 없으면 `termHints: []`를 반환한다. null을 반환하지 않는다.
- 문항당 최대 3개까지 반환하고, 같은 용어는 한 번만 반환한다.
- MVP는 서버 고정 사전 기반으로 구현한다. DB 테이블/관리자 UI는 이번 구현 범위에서 제외한다.

# 🆕 v2.7 하트 0 / 톱니바퀴 부활 정책

- 퀴즈 하트는 attempt 세션 상태로 관리한다. `check` 오답 시 `remainingLives`를 차감하고, 0이 되면 FE는 하트 회복 또는 문제 포기를 선택하게 한다.
- 하트 회복은 `POST /api/mission-attempts/{attemptId}/revive`로 처리한다. 일반 모드 attempt당 1회만 허용하며, 성공 시 톱니바퀴를 차감하고 `remainingLives=3`으로 복구한다.
- 회복하지 않는 경우 `POST /api/mission-attempts/{attemptId}/abandon`을 호출하고 홈으로 이동한다. 이때 에너지 환불, XP, 보상, 진행도, 스트릭, 퀘스트, 업적 반영은 없다.
- `check`는 보상/통계 저장을 만들지 않지만, attempt 복구와 하트 정합성을 위해 `answeredQuestionIds`, `remainingLives`, `wrongCountInSession`, `reviveCount`는 갱신할 수 있다.

# 🆕 v2.6 정본 정책 보정

미션과 퀴즈 출제 기준은 기능 명세서 v3.7와 ERD v2.4를 정본으로 따른다.

- 출제 시점에는 선택된 미션 세트의 정책을 기준으로 문제은행에서 10문항을 런타임에 랜덤 선택한다.
- 미션 식별자와 별 난이도는 세트 정책과 문항 후보 풀을 결정하는 기준으로 사용한다.
- 세트 자체는 고정이지만, 세트 안의 10문항은 사전 고정 배정이 아니라 난이도 비율에 맞춰 런타임 랜덤 선택한다.
- 문제은행 운영 풀은 총 1,056문항이다. 96세트 x 10문항 = 960문항은 플레이 기준 규모이며, 추가 HIGH 96문항은 품질 보정/교체/운영 예비 풀로 관리한다.
- MissionQuestionSetFactory는 전달받은 세트 식별자로 `mission_set`을 찾고, 해당 세트의 `missionId`와 `starLevel` 정책을 기준으로 `missionId + difficulty` 후보 풀에서 문항을 선택해야 한다.

## 1. 개요

미션 / 퀴즈 API는 아이가 선택한 **소단원(mission)** 과 **별 난이도(starLevel 1~3)** 를 기준으로 플레이할 `mission_set`을 선택한다. `setId`는 진행도, attempt, check/submit/report 연결을 위한 학습 단위 식별자로 유지한다.

실제 10문항은 `mission_sets`에서 확인한 `missionId`와 `starLevel` 정책을 기준으로 `question_bank`의 `missionId + difficulty` 후보 풀에서 런타임 선택한다. 선택된 문항 목록은 `quiz_attempts.question_ids_json`에 저장되며, 이후 검증의 기준은 이 attempt 문항 목록이다.

### 핵심 정책

| 항목 | 정책 |
| --- | --- |
| 사용자 선택 단위 | 소단원 + 별 난이도 1~3 |
| 출제 단위 | 문제 세트 1개 = 10문항 |
| 세트 선택 | 동일 소단원/별 난이도의 후보 세트 중 미완료 세트 우선 랜덤 |
| 복습 선택 | 모든 후보 세트를 완료한 경우 완료 세트 중 랜덤 복습 출제 |
| 전체 세트 수 | 16개 소단원 x 3개 별 난이도 x 후보 2세트 = 96세트 |
| 문제은행 운영 규모 | 운영 풀 총 1,056문항. 실제 플레이 세트 고정 배정 문항은 96세트 x 10문항 = 960문항이며, 추가 HIGH 96문항은 품질 보정/교체/운영 예비 풀로 관리 |
| 문항 선택 정책 | `setId`는 진행도/API 호환 학습 단위로 유지하고, 실제 10문항은 `missionId + difficulty` 후보 풀에서 별 난이도 비율에 맞춰 런타임 랜덤 선택 |

## 2. 난이도 모델

### 2-1. 별 난이도와 문항 난이도 분리

`starLevel`은 사용자가 선택하는 세트 난이도다. `QuestionDifficulty`는 문제은행 문항 자체의 난이도다.

| 구분 | 값 | 설명 |
| --- | --- | --- |
| 세트 난이도 | `starLevel = 1 | 2 | 3` | 화면 표시 및 세트 선택 기준 |
| 문항 난이도 | `LOW | MEDIUM | HIGH` | 세트 안에 섞이는 개별 문항 난이도 |

### 2-2. 별 난이도별 문항 구성

| starLevel | 표시 | LOW | MEDIUM | HIGH | 총 문항 |
| --- | --- | --- | --- | --- | --- |
| 1 | 쉬움 | 7 | 2 | 1 | 10 |
| 2 | 보통 | 3 | 5 | 2 | 10 |
| 3 | 어려움 | 2 | 3 | 5 | 10 |

```json
        "starLevel": 1,
        "label": "쉬움",

        "isReviewable": true
      }
    ],
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `UNAUTHORIZED` | 401 | 인증 토큰 없음/만료 |

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. missionId 존재 여부와 stage 잠금 상태 계산
3. energy lazy recovery 계산 후 required=5와 비교
4. mission_set_progress 기준 starLevel별 completedSetCount 계산
5. quiz_attempts 또는 mission_attempts에서 IN_PROGRESS + expires_at > now()인 attempt가 있으면 inProgressAttempt 반환
6. 진행 중 attempt가 없으면 inProgressAttempt=null
```

## 6. GET /api/missions/{missionId}/questions

사용자가 소단원과 별 난이도를 선택했을 때 호출하는 정본 출제 API다.

### Request

```
GET /api/missions/1/questions?starLevel=2
Authorization: Bearer {accessToken}
```

### Path / Query

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `missionId` | Path | Y | 소단원 ID |
| `starLevel` | Query | Y | 1=쉬움, 2=보통, 3=어려움 |

### 서버 선택 규칙

1. `missionId`와 `starLevel`에 연결된 후보 세트를 조회한다.
2. 아이가 아직 완료하지 않은 세트가 있으면 미완료 세트 중 랜덤 선택한다.
3. 후보 세트를 모두 완료했다면 완료 세트 중 랜덤 선택하고 `isReview=true`로 반환한다.
4. 선택된 세트는 항상 10문항이며, 별 난이도별 문항 비율을 만족해야 한다.
5. 문제 조회 시 진행 중 attempt를 생성하거나 재사용하고, 응답에 `attemptId`를 포함한다.

### Response

```json
{
  "success": true,
  "data": {
    "setId": "S0101-L2",
    "attemptId": "8c9d0e1f-1111-2222-3333-444444444444",

      {
        "questionId": "4b8f6f0e-1111-2222-3333-555555555555",
        "questionNo": 1,
        "type": "MULTIPLE",
        "difficulty": "LOW",
        "prompt": "AI가 할 수 있는 일을 고르세요.",
        "choices": ["그림 인식", "숨 쉬기", "밥 먹기", "잠자기"],
        "answerFormat": "SINGLE_CHOICE",
        "termHints": [
          {
            "term": "인식",
            "description": "보고 듣거나 읽은 것을 알아차리는 것을 말해요."
          }
        ]
      }

  }

```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `INVALID_STAR_LEVEL` | 400 | `starLevel`이 1, 2, 3이 아님 |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `MISSION_LOCKED` | 403 | 아직 해금되지 않은 소단원 |
| `MISSION_SET_NOT_READY` | 409 | 해당 난이도 후보 세트가 없거나 10문항 구성이 불완전함 |
| `INSUFFICIENT_ENERGY` | 409 | 학습 시작에 필요한 에너지가 부족함 |

### 사용 용도

## 8. POST /api/mission-sets/{setId}/check

문항 단위 정답 여부를 확인한다. check는 학습 피드백 전용이며 최종 제출/보상 저장 책임을 갖지 않는다.

### Request

```json
{
  "questionId": "4b8f6f0e-1111-2222-3333-555555555555",
  "answer": "그림 인식"
}
```

### Response

```json
{
  "success": true,
  "data": {
    "questionId": "4b8f6f0e-1111-2222-3333-555555555555",
    "isCorrect": true,
    "correctAnswer": "그림 인식",
    "explanation": "AI는 이미지나 소리를 인식할 수 있어요.",
    "remainingLives": 2,
    "canRevive": false,
    "reviveCost": 10,
    "gearBalance": 40
  }
}
```

### 하트 0 응답 예시

```json
{
  "success": true,
  "data": {
    "questionId": "4b8f6f0e-3333-4444-5555-666666666666",
    "isCorrect": false,
    "correctAnswer": "그림 인식",
    "explanation": "AI는 이미지나 소리를 인식할 수 있어요.",
    "remainingLives": 0,
    "canRevive": true,
    "reviveCost": 10,
    "gearBalance": 40,
    "nextActions": ["REVIVE", "ABANDON"]
  }
}
```

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. childId + setId + status=IN_PROGRESS 기준으로 진행 중 quiz_attempt를 찾고, questionId가 attempt.question_ids_json에 포함되는지 검증
3. 서버 정답 키로 해당 문항만 채점
4. 진행 중 attempt 복구를 위해 quiz_attempts.answered_question_ids_json에 questionId를 추가할 수 있음
5. 오답이면 quiz_attempts.remaining_lives를 1 차감하고 wrong_count_in_session을 갱신함
6. remaining_lives가 0이면 FE는 revive 또는 abandon 플로우를 표시함
7. check는 submitted_at, mission_attempts, mission_answer_results, XP/보상/스트릭/펫/퀘스트/업적/통계를 변경하지 않음
```


## 11-C. POST /api/mission-attempts/{attemptId}/revive

하트가 0이 된 진행 중 attempt를 톱니바퀴로 1회 회복한다.

### Request

```json
{ "useCurrency": true }
```

### Response 200

```json
{
  "success": true,
  "data": {
    "attemptId": "8c9d0e1f-1111-2222-3333-444444444444",
    "remainingLives": 3,
    "reviveCount": 1,
    "reviveCost": 10,
    "gearBalance": 30
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `ATTEMPT_NOT_FOUND` | 404 | 존재하지 않거나 본인 attempt가 아님 |
| `ATTEMPT_NOT_REVIVABLE` | 409 | 하트가 0이 아니거나 이미 부활했거나 복습 모드 attempt임 |
| `GEAR_NOT_ENOUGH` | 409 | 톱니바퀴 잔액 부족 |

### 구현 노트

```jsx

2. quiz_attempts를 FOR UPDATE로 조회하고 attempt.child_id == childId 검증
3. status=IN_PROGRESS, isReview=false, remaining_lives=0, revive_count=0 검증
4. child_profiles를 FOR UPDATE로 조회하고 gear >= HEART_REVIVE_GEAR_COST 검증
5. child_profiles.gear 차감
6. currency_transactions에 HEART_REVIVE 원장 기록
7. quiz_attempts.remaining_lives=3, revive_count += 1, revived_at=now() 저장
8. 응답에 remainingLives, reviveCount, gearBalance 반환
```

## 12. 구현 가이드

### Entity / DTO 기준

```java
class MissionSet {
    String setId;        // 예: S0101-L2
    UUID missionId;
    Integer starLevel;   // 1, 2, 3
    Integer variantNo;   // 동일 별 난이도의 후보 세트 번호
}

class MissionQuestionsResponse {
    String setId;
    UUID missionId;
    String missionCode;
    Integer starLevel;
    Integer variantNo;
    Boolean isReview;
    List<QuestionResponse> questions;
}

class QuestionResponse {
    UUID questionId;
    Integer questionNo;
    QuestionType type;
    QuestionDifficulty difficulty;
    String prompt;
    List<String> choices;
    String answerFormat;
    List<TermHintResponse> termHints; // empty list when no matched term
}

class TermHintResponse {
    String term;
    String description;
}
```

### termHints 구현 기준

```java
@Component
class QuestionTermHintService {
    List<TermHintResponse> findHints(String prompt, List<String> choices) {
        // 1. prompt + choices를 하나의 검색 텍스트로 합친다.
        // 2. 서버 고정 용어 사전을 순회하며 포함 여부를 확인한다.
        // 3. 같은 용어는 중복 제거하고 최대 3개까지만 반환한다.
        // 4. 매칭 결과가 없으면 Collections.emptyList()를 반환한다.
    }
}
```

### termHints 고정 사전 예시

| term | description |
| --- | --- |
| 인공지능 | 사람처럼 배우고 판단하도록 만든 컴퓨터 기술이에요. |
| 자료 | 컴퓨터가 배우거나 판단할 때 참고하는 글, 숫자, 그림 같은 정보예요. |
| 편향 | 한쪽으로 치우쳐서 생각하거나 판단하는 것을 말해요. |
| 개인정보 | 이름, 전화번호, 주소처럼 나를 알아볼 수 있게 하는 정보예요. |
| 출처 | 정보가 처음 나온 곳이에요. |

### Repository 기준

```java
List<MissionSet> findByMissionIdAndStarLevel(UUID missionId, int starLevel);

List<Question> findActivePoolByMissionIdAndDifficulty(UUID missionId, QuestionDifficulty difficulty);

List<MissionSetProgress> findByChildIdAndMissionIdAndStarLevel(
    UUID childId,
    UUID missionId,
    int starLevel
);
```

### 주의사항

- `levelNo`는 신규 API 응답과 요청에서 사용하지 않는다.
- `starLevel`은 반드시 1, 2, 3 중 하나여야 한다.
- `difficulty`는 개별 문항의 난이도(`LOW`, `MEDIUM`, `HIGH`)로만 사용한다.
- 클라이언트는 세트를 직접 고르지 않고 `missionId + starLevel`만 전달한다.
- 서버는 선택된 세트의 `setId`를 응답에 포함해 이후 채점/제출/리포트 API가 동일 세트를 기준으로 동작하도록 한다.
- `termHints`는 questions 응답에만 포함한다. check/submit/report의 해설 필드와 섞지 않는다.
- `termHints.description`에는 정답을 직접 알려주는 표현을 넣지 않는다.
- 원본 문제 JSON과 기존 seed SQL은 수정하지 않는다. 문제 조회 응답 DTO 조립 단계에서만 보강한다.
