# 🔥 스트릭 API

> 🆕 **v2.0 반영**: 스트릭은 세트 개수와 무관하게 날짜 기준으로 유지합니다. 오늘 일반 모드로 통과한 학습 세트가 1개 이상이면 스트릭이 유지되며, 복습/실패 제출은 제외합니다.
> 

> ⚠️ **범위 안내**: `GET /streak`는 MVP 범위에 포함하지만, **공동 스트릭 파트너 연결/해제 API는 Post-MVP 후보**입니다.
> 

> 🆕 **톱니바퀴 반영**: 스트릭 보호권은 기존 레벨업 보상 외에 `POST /streak/shields/purchase`로 톱니바퀴를 사용해 구매할 수 있습니다.
> 

## GET /streak

> 스트릭 현황 + 공동 스트릭 파트너 정보 조회
> 

**담당**: BE (문한일) | **인증**: CHILD

**Response 200**

```json
{
  "success": true,
  "data": {
    "continuousDays": 5,
    "lastCompletedDate": "2026-03-28",
    "todaySetCount": 1,
    "shieldCount": 2,
    "partner": {
      "childId": "uuid",
      "nickname": "지우",
      "todayCompleted": true
    }
  }
}
```

> **v1.6**: 파트너 없으면 `"partner": null` 반환
> 

**응답 규칙**

```jsx
- lastCompletedDate != today(KST) 이면 → todaySetCount: 0 반환 (저장값 무시)
- 기존 todayMissionCount 필드를 호환 유지할 경우 설명은 "오늘 완료한 학습 세트 수"로 고정
- partner.todayCompleted = true 조건:
    파트너의 lastCompletedDate == today(KST)
    AND 파트너의 todaySetCount > 0
```

## POST /streak/partner

> 공동 스트릭 파트너 연결 — **Post-MVP 후보**
> 

**담당**: BE (문한일) | **인증**: CHILD

**Request Body**

```json
{ "partnerCode": "719284" }
```

**Response 200**

```json
{
  "success": true,
  "data": { "partner": { "childId": "uuid", "nickname": "지우" } }
}
```

**예외 처리**

| 상황 | HTTP | code | message | 본인 코드 입력 | 400 | BAD_REQUEST | 본인의 코드는 입력할 수 없어요 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 이미 파트너 연결됨 | 409 | CONFLICT | 이미 친구와 연결되어 있어요 | 상대방도 이미 다른 파트너 연결됨 | 409 | CONFLICT | 친구가 이미 다른 친구와 연결되어 있어요 |

**구현 노트**

```jsx
1. partnerCode로 파트너 child 조회 → 없으면 404
2. 트랜잭션 시작
3. 두 child profile row를 항상 같은 순서로 FOR UPDATE  ← deadlock 방지
4. 내가 이미 파트너 연결되어 있는지 재확인 → 있으면 409
5. 상대도 이미 파트너 연결되어 있는지 재확인 → 있으면 409
6. friend_streaks INSERT
7. 커밋
```

## POST /streak/shields/purchase

> 톱니바퀴로 스트릭 보호권을 구매한다.
> 

**담당**: BE (문한일) | **인증**: CHILD

**Request Body**

```json
{ "count": 1 }
```

**Response 200**

```json
{
  "success": true,
  "data": {
    "shieldCount": 3,
    "purchasedCount": 1,
    "unitCost": 30,
    "gearBalance": 70
  }
}
```

**예외 처리**

| 상황 | HTTP | code | message |
| --- | --- | --- | --- |
| 톱니바퀴 부족 | 409 | GEAR_NOT_ENOUGH | 톱니바퀴가 부족해요 |
| 구매 수량 오류 | 400 | BAD_REQUEST | 구매 수량을 다시 확인해 주세요 |

**구현 노트**

```jsx
1. CHILD JWT 검증 후 childId 추출
2. child_profiles row를 FOR UPDATE로 조회
3. cost = STREAK_SHIELD_COST(30) * count 계산
4. gear >= cost 검증
5. child_profiles.gear -= cost
6. child_profiles.shield_count += count
7. currency_transactions에 STREAK_SHIELD_PURCHASE 기록
8. 응답에 최신 shieldCount, gearBalance 반환
```

// streak_records 테이블 (child_id = PK, 1:1 매핑)
@Entity @Table(name = "streak_records")
public class StreakRecord {
    @Id @Column(name = "child_id")         private UUID childId;
    @Column(name = "continuous_days")      private int continuousDays = 0;
    @Column(name = "last_completed_date")  private LocalDate lastCompletedDate; // KST
    @Column(name = "today_set_count")      private int todaySetCount = 0;
    // 하위 호환이 필요하면 DB 컬럼은 today_mission_count를 유지하되 의미를 today_set_count로 정의
}

// child_profiles 추가 필드

// friend_streaks 테이블 (Post-MVP 1차)

public class FriendStreak {

    @Column(name = "child_id")   private UUID childId;   // 나

### GET /streak — 조회 로직

```java
public StreakResponse getStreak(UUID childId) {
    StreakRecord streak = streakRepo.findById(childId).orElseThrow();
    ChildProfile profile = profileRepo.findById(childId).orElseThrow();
    LocalDate today = LocalDate.now(ZoneId.of("Asia/Seoul"));

    // 핵심: lastCompletedDate != today 이면 저장값 무시하고 0 반환
    int todayCount = today.equals(streak.getLastCompletedDate())
        ? streak.getTodaySetCount() : 0;

    // 파트너 없으면 null 반환 (빈 객체 아님!)
    PartnerDto partner = friendStreakRepo.findByChildId(childId)
        .map(fs -> buildPartnerDto(fs.getPartnerId(), today))
        .orElse(null);

    return new StreakResponse(streak.getContinuousDays(),
        streak.getLastCompletedDate(), todayCount,
        profile.getShieldCount(), partner);
}
```

### StreakService.checkIn() — MissionService.submit() 후 호출

```java
/**
 * 학습 세트 submit 통과 후 호출. 스트릭 증가 + 마일스톤 보상 연동.
 * 반드시 같은 트랜잭션 내에서 실행되어야 함.
 */
@Transactional
public List<RewardDto> checkIn(UUID childId) {
    StreakRecord streak = streakRepo.findByIdWithLock(childId).orElseThrow();
    LocalDate today = LocalDate.now(ZoneId.of("Asia/Seoul"));
    List<RewardDto> rewards = new ArrayList<>();

    if (today.equals(streak.getLastCompletedDate())) {
        // 오늘 이미 체크인 — 진행도만 증가
        streak.setTodaySetCount(streak.getTodaySetCount() + 1);
    } else {
        // 날짜 점프 판단
        boolean consecutive = today.minusDays(1).equals(streak.getLastCompletedDate());
        streak.setContinuousDays(consecutive ? streak.getContinuousDays() + 1 : 1);
        streak.setLastCompletedDate(today);
        streak.setTodaySetCount(1);

        // 마일스톤 보상 (7일: RARE, 30일: EPIC)
        int days = streak.getContinuousDays();
        if (days == 7 || days == 30) {
            TicketType type = days == 7 ? TicketType.RARE : TicketType.EPIC;
            ticketRepo.save(new Ticket(childId, type));
            rewards.add(new RewardDto("TICKET", type.name(), 1,
                "STREAK_MILESTONE_" + days + "D"));
        }
    }
    return rewards;
}
```

### 자정 KST 스트릭 소멸 스케줄러

```java
// @EnableScheduling 활성화 필수!
@Scheduled(cron = "0 5 0 * * *", zone = "Asia/Seoul")
@Transactional
public void processStreakReset() {
    LocalDate yesterday = LocalDate.now(ZoneId.of("Asia/Seoul")).minusDays(1);
    List<StreakRecord> missed = streakRepo.findMissedChildren(yesterday);
    // missed = last_completed_date < yesterday OR last_completed_date IS NULL

    for (StreakRecord s : missed) {
        ChildProfile p = profileRepo.findById(s.getChildId()).orElse(null);
        if (p == null) continue;

        if (p.getShieldCount() > 0) {
            p.setShieldCount(p.getShieldCount() - 1); // 쉴드 소비 → streak 유지
        } else {
            s.setContinuousDays(0); // streak 0 리셋
        }
    }
}
```

### ⚠️ 구현 주의사항

```jsx
1. todaySetCount 응답 규칙:
   lastCompletedDate != today(KST)이면 반드시 0 반환 (저장값 무시)
   todayMissionCount를 유지하는 경우에도 의미는 오늘 완료한 학습 세트 수로 동일하게 정의

2. partner 없으면 null 반환 (빈 객체 {} 아님)

3. 마일스톤 보상은 streak.continuousDays가 정확히 7 또는 30일 때만
   (30일 이후 60, 90일 추가 마일스톤 구현 시 쉽게 확장 가능)

4. 자정 스케줄러: @EnableScheduling + JVM 타임존 Asia/Seoul 설정 필수

5. deadlock 방지: POST /streak/partner에서 두 child_id를 항상
   작은 UUID 순서로 FOR UPDATE 잠금 (min/max 정렬)
```
