# 🆕 v3.1 핵심 변경 요약

> 💡 **팀원에게**: 구현 피드백 기준으로 미션/퀴즈 API 계약의 남은 불일치를 보정합니다. 통합 문서의 변경 요약도 하위 미션 API와 같은 `stages[].missions[].starLevels[]` 구조를 정본으로 둡니다.
> 

| # | 변경 항목 | 한 줄 요약 | 영향 담당 |
| --- | --- | --- | --- |
| 1 | **학습맵 응답 구조 보정** | `GET /missions` 변경 요약을 `levels[].stages[].sets[]`가 아니라 `stages[].missions[].starLevels[]` 기준으로 정리 | BE/FE |
| 2 | **setId 역할 명확화** | `setId`는 진행도/API 호환 학습 단위이며, 실제 문항은 `missionId + difficulty` 후보 풀에서 선택 | BE |
| 3 | **ID/예시 정합성 보정** | `missionId`, `questionId`, `attemptId`는 UUID, `setId`는 문자열 예시로 통일 | BE/FE |
| 4 | **score/rewards 계약 통일** | 외부 `score`는 100점 환산 점수, `rewards`는 `{ gear, exp, fragments }` 객체로 통일 | BE/FE |

# 🆕 v2.3 핵심 변경 요약

> 💡 **팀원에게**: 미션/퀴즈 출제 정책은 `6레벨(levelNo)`이 아니라 `소단원별 3난이도(starLevel 1~3)` 기준으로 확정합니다. 클라이언트는 `missionId + starLevel`만 전달하고, 서버가 준비된 후보 세트 중 하나를 랜덤 선택해 `setId`를 반환합니다.
> 

| # | 변경 항목 | 한 줄 요약 | 영향 담당 |
| --- | --- | --- | --- |
| 1 | **3난이도 starLevel 확정** | 사용자 선택 난이도는 `starLevel=1|2|3`만 사용. `levelNo` 6레벨 정책은 신규 API에서 제거 | PM/BE/FE |
| 2 | **랜덤 세트 출제 API 정본화** | `GET /missions/{missionId}/questions?starLevel={1|2|3}`가 일반 학습 진입 API. 서버가 미완료 후보 우선 랜덤 선택 | BE/FE |
| 3 | **문항 난이도와 세트 난이도 분리** | `difficulty=LOW|MEDIUM|HIGH`는 개별 문항 난이도, `starLevel`은 세트 표시/선택 난이도 | BE/FE |
| 4 | **문항 비율 확정** | 별 1개 `7:2:1`, 별 2개 `3:5:2`, 별 3개 `2:3:5`로 LOW/MEDIUM/HIGH를 섞어 출제 | PM/BE |

# 🆕 v2.2 핵심 변경 요약

> 💡 **팀원에게**: v2.0의 `mission-sets/{setId}` 정본 계약은 유지하되, 현재 구현에서 사용하는 `mission-sets/{setId}` 기반 라우트를 정본 API로 문서화한 버전입니다.
> 

> 추가 결정: 퀴즈 하트(lives)는 세션 내부 목숨 UI로 유지하고, 에너지는 계정 단위 energy로 분리합니다. 에너지는 최대 20, 일반 모드 학습 세트 시작 시 5 차감, 10분마다 1 회복, 복습 모드 차감 없음입니다.
> 

| # | 변경 항목 | 한 줄 요약 | 영향 담당 |
| --- | --- | --- | --- |
| 1 | **missionId 기반 문제 조회 호환 API 추가** | `GET /missions/{missionId}/questions`를 호환 경로로 문서화. 내부 처리는 현재 진행 가능한 `setId`를 선택해 `mission-sets/{setId}`와 동일하게 수행 | BE/FE |
| 2 | **setId 기반 check/submit/report 정본화** | `POST /mission-sets/{setId}/check`, `POST /mission-sets/{setId}/submit`, `GET /mission-sets/{setId}/report`를 정본 경로로 문서화하고, missionId 기반 경로는 신규 구현 대상에서 제외 | BE/FE |
| 3 | **정본 경로 유지 명시** | 신규 구현은 계속 `mission-sets/{setId}`를 우선 사용하고, missionId 경로는 기존 FE/마이그레이션 호환용으로 유지 | BE/FE/PM |
