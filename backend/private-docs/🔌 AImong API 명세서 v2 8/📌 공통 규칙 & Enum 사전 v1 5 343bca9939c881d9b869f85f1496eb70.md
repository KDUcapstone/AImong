## 1. 공통 응답 규칙

모든 API는 성공/실패 여부를 `success`로 구분한다.

### 성공 응답

```json
{
  "success": true,
  "data": {}
}
```

### 실패 응답

```json
{
  "success": false,
  "error": {
    "code": "INVALID_STAR_LEVEL",
    "message": "starLevel은 1, 2, 3 중 하나여야 합니다."
  }
}
```

## 2. 인증 규칙

### Authorization Header

```
Authorization: Bearer {accessToken}
```

### 토큰 정책

| 항목 | 정책 |
| --- | --- |
| Access Token | API 호출 인증에 사용 |
| Refresh Token | MVP 미사용. CHILD는 `sessionToken` 단일 JWT + `session_version` 검증으로 관리 |
| 부모 계정 | 자녀 관리, 결제, 설정 권한 |
| 자녀 계정 | 학습, 미션, 보상, 펫 성장 권한 |

### 인증 책임 범위

| 항목 | 정책 |
| --- | --- |
| 부모 인증 | Firebase ID Token을 Spring Security에서 검증 |
| 자녀 인증 | 백엔드가 발급한 CHILD JWT를 Spring Security에서 검증 |
| Supabase | 현재는 Auth 주체가 아니라 Postgres DB로 사용. 앱 JWT 자동 검증 대상 아님 |
| 로그아웃 | `session_version` 증가 또는 FCM 토큰 삭제 API로 처리 |

## 3. 공통 에러 코드

| 코드 | HTTP | 설명 |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | 인증 토큰이 없거나 유효하지 않음 |
| `FORBIDDEN` | 403 | 권한이 없음 |
| `NOT_FOUND` | 404 | 요청 리소스를 찾을 수 없음 |
| `VALIDATION_ERROR` | 400 | 요청 값 검증 실패 |
| `INTERNAL_SERVER_ERROR` | 500 | 서버 내부 오류 |

### 미션 / 퀴즈 전용 에러

| 코드 | HTTP | 설명 |
| --- | --- | --- |
| `INVALID_STAR_LEVEL` | 400 | `starLevel`이 1, 2, 3이 아님 |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `MISSION_LOCKED` | 403 | 아직 해금되지 않은 소단원 |
| `MISSION_SET_NOT_FOUND` | 404 | 존재하지 않는 문제 세트 |
| `MISSION_SET_NOT_READY` | 409 | 후보 세트가 없거나 10문항 구성이 불완전함 |
| `QUESTION_NOT_FOUND` | 404 | 존재하지 않는 문제 |
| `INVALID_ANSWER_FORMAT` | 400 | 답안 형식이 문제 유형과 맞지 않음 |
| `INSUFFICIENT_ENERGY` | 409 | 학습 시작에 필요한 에너지가 부족함 |

`INVALID_LEVEL`은 6레벨 정책에서 사용하던 코드이므로 신규 미션/퀴즈 API에서는 사용하지 않는다.

## 4. 전역 Enum

### QuestionDifficulty

개별 문항의 난이도다. 세트 선택 난이도와 혼동하지 않는다.

```
LOW
MEDIUM
HIGH
```

### StarLevel

사용자가 선택하는 소단원별 세트 난이도다.

| 값 | 표시 | 문항 구성 |
| --- | --- | --- |
| 1 | 쉬움 | LOW 7 / MEDIUM 2 / HIGH 1 |
| 2 | 보통 | LOW 3 / MEDIUM 5 / HIGH 2 |
| 3 | 어려움 | LOW 2 / MEDIUM 3 / HIGH 5 |

### QuestionType

```
OX
MULTIPLE
FILL
SITUATION
```

### AttemptStatus

```
IN_PROGRESS
SUBMITTED
EXPIRED
ABANDONED
```

- `ABANDONED`는 사용자가 진행 중 attempt를 명시적으로 포기한 상태다. 이후 submit/check/restore 대상에서 제외한다.

### RewardType

```
COIN
EXP
PET_FRAGMENT
ITEM
```

## 5. 미션 세트 규칙

### 기본 규칙

| 항목 | 규칙 |
| --- | --- |
| 세트 선택 기준 | `missionId + starLevel` |
| 세트 후보 | 동일 소단원/별 난이도마다 후보 2세트 |
| 출제 방식 | 미완료 후보 우선 랜덤, 모두 완료 시 완료 후보 중 랜덤 복습 |
| 세트 문항 수 | 10문항 고정 |
| 전체 세트 수 | 16개 소단원 x 3개 별 난이도 x 2개 후보 = 96세트 |

### 필드 의미

| 필드 | 의미 |
| --- | --- |
| `starLevel` | 세트 난이도. 1, 2, 3만 허용 |
| `variantNo` | 동일 소단원/별 난이도 내 후보 세트 번호 |
| `difficulty` | 개별 문항 난이도. `LOW | MEDIUM | HIGH` |
| `setId` | 서버가 선택한 실제 문제 세트 ID |

## 7. 날짜 / 시간 규칙

- 모든 저장 시간은 UTC 기준으로 관리한다.
- 클라이언트 표시는 사용자 로컬 타임존을 적용한다.
- API 응답은 ISO-8601 문자열을 사용한다.

```json
{
  "createdAt": "2026-05-10T09:00:00Z"
}
```
