# 🎯 미션 / 퀴즈 API v2.6

> **버전**: v2.6
> 

> **수정일**: 2026-05-12
> 

> **변경 기준**: AImong의 출제는 고정 세트 기반 런타임 문항 선택 방식이다. `mission_sets.set_id`는 학습 세트/진행도/복습/채점 기준으로 고정되며, 서버는 해당 세트의 mission/starLevel/난이도 비율 정책에 맞춰 문제은행에서 10문항을 런타임 랜덤 선택한다.
> 

> 🆕 **v2.6 반영**: 1,056문항 운영 풀과 HIGH 추가 생성 정책은 유지하되, 실제 출제는 96세트/960문항 고정 세트 기준으로 통일한다. 추가 96문항은 품질 보정/교체/운영 예비 풀로 관리하며 런타임 난이도 비율 재조합에는 사용하지 않는다.
> 

# 🆕 v2.6 정본 정책 보정

미션과 퀴즈 출제 기준은 기능 명세서 v3.4와 ERD v2.2를 정본으로 따른다.

- 출제 시점에는 선택된 미션 세트의 정책을 기준으로 문제은행에서 10문항을 런타임에 랜덤 선택한다.
- 미션 식별자와 별 난이도는 세트 정책과 문항 후보 풀을 결정하는 기준으로 사용한다.
- 세트 자체는 고정이지만, 세트 안의 10문항은 사전 고정 배정이 아니라 난이도 비율에 맞춰 런타임 랜덤 선택한다.
- 문제은행 운영 풀은 총 1,056문항이다. 이 중 실제 플레이 세트에 고정 배정되는 문항은 96세트 x 10문항 = 960문항이다.
- 추가 HIGH 96문항은 품질 보정, 세트 교체, 운영 예비 풀로 유지하며, 세트별 난이도 비율에 맞춘 런타임 문항 선택 후보로 사용할 수 있다.
- MissionQuestionSetFactory는 전달받은 세트 식별자를 무시하지 않고 해당 세트의 문항만 조회해야 한다.

## 1. 개요

미션 / 퀴즈 API는 아이가 선택한 **소단원(mission)** 과 **별 난이도(starLevel 1~3)** 를 기준으로 플레이할 `mission_set`을 선택한 뒤, 해당 `setId`에 사전 배정된 10문항을 그대로 제공한다.

기존의 `MissionQuestionSetFactory`처럼 `setId`를 무시하고 `missionId + difficulty/starLevel` 풀에서 문항을 런타임 재조합하는 방식은 사용하지 않는다. 화면과 API는 `starLevel` 1, 2, 3을 노출할 수 있지만, 실제 문항 조회의 최종 기준은 항상 `mission_sets.set_id`다.

### 핵심 정책

| 항목 | 정책 |
| --- | --- |
| 사용자 선택 단위 | 소단원 + 별 난이도 1~3 |
| 출제 단위 | 문제 세트 1개 = 10문항 |
| 세트 선택 | 동일 소단원/별 난이도의 후보 세트 중 미완료 세트 우선 랜덤 |
| 복습 선택 | 모든 후보 세트를 완료한 경우 완료 세트 중 랜덤 복습 출제 |
| 전체 세트 수 | 16개 소단원 x 3개 별 난이도 x 후보 2세트 = 96세트 |
| 문제은행 운영 규모 | 운영 풀 총 1,056문항. 실제 플레이 세트 고정 배정 문항은 96세트 x 10문항 = 960문항이며, 추가 HIGH 96문항은 품질 보정/교체/운영 예비 풀로 관리 |
| 문항 선택 정책 | `setId`는 고정 세트 기준으로 유지하고, 세트 안의 10문항은 난이도 비율에 맞춰 문제은행에서 런타임 랜덤 선택 |

## 2. 난이도 모델

### 2-1. 별 난이도와 문항 난이도 분리

`starLevel`은 사용자가 선택하는 세트 난이도다. `QuestionDifficulty`는 문제은행 문항 자체의 난이도다.

| 구분 | 값 | 설명 |
| --- | --- | --- |
| 세트 난이도 | `starLevel = 1 | 2 | 3` | 화면 표시 및 세트 선택 기준 |
| 문항 난이도 | `LOW | MEDIUM | HIGH` | 세트 안에 섞이는 개별 문항 난이도 |

### 2-2. 별 난이도별 문항 구성

| starLevel | 표시 | LOW | MEDIUM | HIGH | 총 문항 |
| --- | --- | --- | --- | --- | --- |
| 1 | 쉬움 | 7 | 2 | 1 | 10 |
| 2 | 보통 | 3 | 5 | 2 | 10 |
| 3 | 어려움 | 2 | 3 | 5 | 10 |

## 5. GET /api/missions/{missionId}/status

소단원 상세 진입 전 플레이 가능 상태를 조회한다. FE는 이 API로 잠금, 에너지 부족, 진행 중 attempt 존재 여부를 확인한 뒤 문제 조회 API를 호출한다.

### Request

```jsx
GET /api/missions/1/status
Authorization: Bearer {accessToken}
```

### Response 200

```json
{
  "success": true,
  "data": {
    "missionId": 1,
    "missionCode": "S1-M1",
    "title": "AI란 무엇일까?",
    "isUnlocked": true,
    "canStartMission": true,
    "energy": {
      "current": 15,
      "required": 5,
      "maxEnergy": 20,
      "nextEnergyRecoverAt": "2026-05-10T09:10:00Z"
    },
    "starLevels": [
      {
        "starLevel": 1,
        "label": "쉬움",
        "totalSetCount": 2,
        "completedSetCount": 1,
        "isPlayable": true,
        "isReviewable": true
      }
    ],
    "inProgressAttempt": {
      "attemptId": "8c9d0e1f-...",
      "setId": 37,
      "starLevel": 1,
      "expiresAt": "2026-05-10T09:20:00Z"
    }
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `UNAUTHORIZED` | 401 | 인증 토큰 없음/만료 |

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. missionId 존재 여부와 stage 잠금 상태 계산
3. energy lazy recovery 계산 후 required=5와 비교
4. mission_set_progress 기준 starLevel별 completedSetCount 계산
5. quiz_attempts 또는 mission_attempts에서 IN_PROGRESS + expires_at > now()인 attempt가 있으면 inProgressAttempt 반환
6. 진행 중 attempt가 없으면 inProgressAttempt=null
```

## 6. GET /api/missions/{missionId}/questions

사용자가 소단원과 별 난이도를 선택했을 때 호출하는 정본 출제 API다.

### Request

```
GET /api/missions/1/questions?starLevel=2
Authorization: Bearer {accessToken}
```

### Path / Query

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `missionId` | Path | Y | 소단원 ID |
| `starLevel` | Query | Y | 1=쉬움, 2=보통, 3=어려움 |

### 서버 선택 규칙

1. `missionId`와 `starLevel`에 연결된 후보 세트를 조회한다.
2. 아이가 아직 완료하지 않은 세트가 있으면 미완료 세트 중 랜덤 선택한다.
3. 후보 세트를 모두 완료했다면 완료 세트 중 랜덤 선택하고 `isReview=true`로 반환한다.
4. 선택된 세트는 항상 10문항이며, 별 난이도별 문항 비율을 만족해야 한다.
5. 문제 조회 시 진행 중 attempt를 생성하거나 재사용하고, 응답에 `attemptId`를 포함한다.

### Response

```json
{
  "success": true,
  "data": {
    "setId": 37,
    "attemptId": "8c9d0e1f-...",
    "missionId": 1,
    "missionCode": "S1-M1",
    "starLevel": 2,
    "label": "보통",
    "variantNo": 1,
    "isReview": false,
    "energyCost": 1,
    "energyBefore": 5,
    "energyAfter": 4,
    "questionCount": 10,
    "questions": [
      {
        "questionId": 1001,
        "questionNo": 1,
        "type": "MULTIPLE",
        "difficulty": "LOW",
        "prompt": "AI가 할 수 있는 일을 고르세요.",
        "choices": ["그림 인식", "숨 쉬기", "밥 먹기", "잠자기"],
        "answerFormat": "SINGLE_CHOICE"
      }
    ]
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `INVALID_STAR_LEVEL` | 400 | `starLevel`이 1, 2, 3이 아님 |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `MISSION_LOCKED` | 403 | 아직 해금되지 않은 소단원 |
| `MISSION_SET_NOT_READY` | 409 | 해당 난이도 후보 세트가 없거나 10문항 구성이 불완전함 |
| `INSUFFICIENT_ENERGY` | 409 | 학습 시작에 필요한 에너지가 부족함 |

## 7. GET /api/mission-sets/{setId}/questions

특정 세트를 직접 조회한다. 일반 학습 진입은 `/api/missions/{missionId}/questions?starLevel=...`를 우선 사용한다.

### 사용 용도

- 완료 세트 복습
- 관리자/운영 검수
- QA 재현
- 기존 클라이언트 호환

응답 본문은 랜덤 출제 API와 동일하되, 서버가 세트를 새로 고르지 않고 전달받은 `setId`를 사용한다.

## 8. POST /api/mission-sets/{setId}/check

문항 단위 정답 여부를 확인한다. check는 학습 피드백 전용이며 최종 제출/보상 저장 책임을 갖지 않는다.

### Request

```json
{
  "questionId": 1001,
  "answer": "그림 인식"
}
```

### Response

```json
{
  "success": true,
  "data": {
    "questionId": 1001,
    "isCorrect": true,
    "correctAnswer": "그림 인식",
    "explanation": "AI는 이미지나 소리를 인식할 수 있어요."
  }
}
```

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. setId와 questionId가 같은 세트에 속하는지 검증
3. 서버 정답 키로 해당 문항만 채점
4. 진행 중 attempt 복구를 위해 quiz_attempts.answered_question_ids_json에 questionId를 추가할 수 있음
5. check는 submitted_at, mission_attempts, mission_answer_results, XP/보상/스트릭/펫/퀘스트/업적/통계를 변경하지 않음
```

## 11-A. GET /api/mission-attempts/{attemptId}

진행 중 attempt를 복구하거나 현재 상태를 조회한다. 앱 강제 종료/네트워크 재시도/화면 복귀 시 사용한다.

### Response 200

```json
{
  "success": true,
  "data": {
    "attemptId": "8c9d0e1f-...",
    "setId": 37,
    "missionId": 1,
    "starLevel": 2,
    "status": "IN_PROGRESS",
    "isReview": false,
    "expiresAt": "2026-05-10T09:20:00Z",
    "remainingSeconds": 540,
    "answeredQuestionIds": [1001, 1002],
    "questionCount": 10
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `ATTEMPT_NOT_FOUND` | 404 | 존재하지 않거나 본인 attempt가 아님 |
| `ATTEMPT_EXPIRED` | 409 | 만료된 attempt |

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. attempt.child_id == childId 검증
3. status=IN_PROGRESS이고 expires_at > now()이면 복구 가능
4. 문제 원문 재전송이 필요하면 GET /mission-sets/{setId}/questions?attemptId={attemptId} 호환 파라미터를 Post-MVP로 검토
```

## 11-B. POST /api/mission-attempts/{attemptId}/abandon

퀴즈 중도 이탈을 명시적으로 기록한다. 뒤로가기/나가기 버튼/앱 종료 복구 포기 시 호출한다.

### Request

```json
{ "reason": "USER_EXIT" }
```

| reason | 설명 |
| --- | --- |
| USER_EXIT | 사용자가 나가기 선택 |
| APP_BACKGROUND_TIMEOUT | 앱 백그라운드/복귀 제한 초과 |
| RESTART | 새 문제 세트 시작을 위해 기존 attempt 포기 |

### Response 200

```json
{
  "success": true,
  "data": {
    "abandoned": true,
    "attemptId": "8c9d0e1f-...",
    "status": "ABANDONED",
    "energyRefunded": false
  }
}
```

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. attempt.child_id == childId 검증
3. IN_PROGRESS 상태만 ABANDONED로 변경 가능
4. 기본 정책: 일반 모드 시작 시 차감한 에너지는 환불하지 않음
5. 보상/진행도/스트릭/퀘스트/업적은 반영하지 않음
6. 이미 SUBMITTED/EXPIRED/ABANDONED면 409 ATTEMPT_ALREADY_CLOSED 반환
```

List<MissionSet> findByMissionIdAndStarLevel(Long missionId, int starLevel);

### 주의사항

- `levelNo`는 신규 API 응답과 요청에서 사용하지 않는다.
- `starLevel`은 반드시 1, 2, 3 중 하나여야 한다.
- `difficulty`는 개별 문항의 난이도(`LOW`, `MEDIUM`, `HIGH`)로만 사용한다.
- 클라이언트는 세트를 직접 고르지 않고 `missionId + starLevel`만 전달한다.
- 서버는 선택된 세트의 `setId`를 응답에 포함해 이후 채점/제출/리포트 API가 동일 세트를 기준으로 동작하도록 한다.
