# 🎯 미션 / 퀴즈 API v2.4

> **버전**: v2.4
> 

> **수정일**: 2026-05-10
> 

> **변경 기준**: 소단원별 난이도 선택은 `starLevel` 3개로 고정한다. 사용자가 소단원과 난이도를 선택하면 준비된 후보 세트 중 하나를 랜덤으로 출제한다.
> 

> 🆕 **v2.4 반영**: 미션 진입 전 상태 조회, 진행 중 attempt 복구, 중도 이탈(abandon) API를 추가한다.
> 

## 1. 개요

미션 / 퀴즈 API는 아이가 선택한 **소단원(mission)** 과 **별 난이도(starLevel 1~3)** 를 기준으로 학습 문제 10문항을 제공한다.

기존의 6레벨(`levelNo`) 고정 출제 방식은 사용하지 않는다. 화면과 API는 `starLevel` 1, 2, 3만 노출하며, 서버는 해당 별 난이도에 연결된 후보 세트 중 하나를 선택한다.

### 핵심 정책

| 항목 | 정책 |
| --- | --- |
| 사용자 선택 단위 | 소단원 + 별 난이도 1~3 |
| 출제 단위 | 문제 세트 1개 = 10문항 |
| 세트 선택 | 동일 소단원/별 난이도의 후보 세트 중 미완료 세트 우선 랜덤 |
| 복습 선택 | 모든 후보 세트를 완료한 경우 완료 세트 중 랜덤 복습 출제 |
| 전체 세트 수 | 16개 소단원 x 3개 별 난이도 x 후보 2세트 = 96세트 |
| 문제은행 운영 풀 | 기존 960문항 유지 + HIGH 96문항 추가 = 1,056문항 |
| 문항 난이도 비율 | 별 1개 7:2:1, 별 2개 3:5:2, 별 3개 2:3:5 |

---

## 2. 난이도 모델

### 2-1. 별 난이도와 문항 난이도 분리

`starLevel`은 사용자가 선택하는 세트 난이도다. `QuestionDifficulty`는 문제은행 문항 자체의 난이도다.

| 구분 | 값 | 설명 |
| --- | --- | --- |
| 세트 난이도 | `starLevel = 1 | 2 | 3` | 화면 표시 및 세트 선택 기준 |
| 문항 난이도 | `LOW | MEDIUM | HIGH` | 세트 안에 섞이는 개별 문항 난이도 |

### 2-2. 별 난이도별 문항 구성

| starLevel | 표시 | LOW | MEDIUM | HIGH | 총 문항 |
| --- | --- | --- | --- | --- | --- |
| 1 | 쉬움 | 7 | 2 | 1 | 10 |
| 2 | 보통 | 3 | 5 | 2 | 10 |
| 3 | 어려움 | 2 | 3 | 5 | 10 |

## 3. API 목록

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/missions` | 스테이지/소단원/별 난이도 목록 조회 |

## 5. GET /api/missions/{missionId}/status

소단원 상세 진입 전 플레이 가능 상태를 조회한다. FE는 이 API로 잠금, 에너지 부족, 진행 중 attempt 존재 여부를 확인한 뒤 문제 조회 API를 호출한다.

### Request

```jsx
GET /api/missions/1/status
Authorization: Bearer {accessToken}
```

### Response 200

```json
{
  "success": true,
  "data": {
    "missionId": 1,
    "missionCode": "S1-M1",
    "title": "AI란 무엇일까?",
    "isUnlocked": true,
    "canStartMission": true,
    "energy": {
      "current": 15,
      "required": 5,
      "maxEnergy": 20,
      "nextEnergyRecoverAt": "2026-05-10T09:10:00Z"
    },
    "starLevels": [
      {
        "starLevel": 1,
        "label": "쉬움",
        "totalSetCount": 2,
        "completedSetCount": 1,
        "isPlayable": true,
        "isReviewable": true
      }
    ],
    "inProgressAttempt": {
      "attemptId": "8c9d0e1f-...",
      "setId": 37,
      "starLevel": 1,
      "expiresAt": "2026-05-10T09:20:00Z"
    }
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `UNAUTHORIZED` | 401 | 인증 토큰 없음/만료 |

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. missionId 존재 여부와 stage 잠금 상태 계산
3. energy lazy recovery 계산 후 required=5와 비교
4. mission_set_progress 기준 starLevel별 completedSetCount 계산
5. quiz_attempts 또는 mission_attempts에서 IN_PROGRESS + expires_at > now()인 attempt가 있으면 inProgressAttempt 반환
6. 진행 중 attempt가 없으면 inProgressAttempt=null
```

## 6. GET /api/missions/{missionId}/questions

사용자가 소단원과 별 난이도를 선택했을 때 호출하는 정본 출제 API다.

### Request

```
GET /api/missions/1/questions?starLevel=2
Authorization: Bearer {accessToken}
```

### Path / Query

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `missionId` | Path | Y | 소단원 ID |
| `starLevel` | Query | Y | 1=쉬움, 2=보통, 3=어려움 |

### 서버 선택 규칙

1. `missionId`와 `starLevel`에 연결된 후보 세트를 조회한다.
2. 아이가 아직 완료하지 않은 세트가 있으면 미완료 세트 중 랜덤 선택한다.
3. 후보 세트를 모두 완료했다면 완료 세트 중 랜덤 선택하고 `isReview=true`로 반환한다.
4. 선택된 세트는 항상 10문항이며, 별 난이도별 문항 비율을 만족해야 한다.
5. 문제 조회 시 진행 중 attempt를 생성하거나 재사용하고, 응답에 `attemptId`를 포함한다.

### Response

```json
{
  "success": true,
  "data": {
    "setId": 37,
    "attemptId": "8c9d0e1f-...",
    "missionId": 1,
    "missionCode": "S1-M1",
    "starLevel": 2,
    "label": "보통",
    "variantNo": 1,
    "isReview": false,
    "energyCost": 1,
    "energyBefore": 5,
    "energyAfter": 4,
    "questionCount": 10,
    "questions": [
      {
        "questionId": 1001,
        "questionNo": 1,
        "type": "MULTIPLE",
        "difficulty": "LOW",
        "prompt": "AI가 할 수 있는 일을 고르세요.",
        "choices": ["그림 인식", "숨 쉬기", "밥 먹기", "잠자기"],
        "answerFormat": "SINGLE_CHOICE"
      }
    ]
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `INVALID_STAR_LEVEL` | 400 | `starLevel`이 1, 2, 3이 아님 |
| `MISSION_NOT_FOUND` | 404 | 존재하지 않는 소단원 |
| `MISSION_LOCKED` | 403 | 아직 해금되지 않은 소단원 |
| `MISSION_SET_NOT_READY` | 409 | 해당 난이도 후보 세트가 없거나 10문항 구성이 불완전함 |
| `INSUFFICIENT_ENERGY` | 409 | 학습 시작에 필요한 에너지가 부족함 |

## 6. GET /api/mission-sets/{setId}/questions

특정 세트를 직접 조회한다. 일반 학습 진입은 `/api/missions/{missionId}/questions?starLevel=...`를 우선 사용한다.

### 사용 용도

- 완료 세트 복습
- 관리자/운영 검수
- QA 재현
- 기존 클라이언트 호환

응답 본문은 랜덤 출제 API와 동일하되, 서버가 세트를 새로 고르지 않고 전달받은 `setId`를 사용한다.

## 9-A. GET /api/mission-attempts/{attemptId}

진행 중 attempt를 복구하거나 현재 상태를 조회한다. 앱 강제 종료/네트워크 재시도/화면 복귀 시 사용한다.

### Response 200

```json
{
  "success": true,
  "data": {
    "attemptId": "8c9d0e1f-...",
    "setId": 37,
    "missionId": 1,
    "starLevel": 2,
    "status": "IN_PROGRESS",
    "isReview": false,
    "expiresAt": "2026-05-10T09:20:00Z",
    "remainingSeconds": 540,
    "answeredQuestionIds": [1001, 1002],
    "questionCount": 10
  }
}
```

### 에러

| 코드 | HTTP | 상황 |
| --- | --- | --- |
| `ATTEMPT_NOT_FOUND` | 404 | 존재하지 않거나 본인 attempt가 아님 |
| `ATTEMPT_EXPIRED` | 409 | 만료된 attempt |

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. attempt.child_id == childId 검증
3. status=IN_PROGRESS이고 expires_at > now()이면 복구 가능
4. 문제 원문 재전송이 필요하면 GET /mission-sets/{setId}/questions?attemptId={attemptId} 호환 파라미터를 Post-MVP로 검토
```

## 9-B. POST /api/mission-attempts/{attemptId}/abandon

퀴즈 중도 이탈을 명시적으로 기록한다. 뒤로가기/나가기 버튼/앱 종료 복구 포기 시 호출한다.

### Request

```json
{ "reason": "USER_EXIT" }
```

| reason | 설명 |
| --- | --- |
| USER_EXIT | 사용자가 나가기 선택 |
| APP_BACKGROUND_TIMEOUT | 앱 백그라운드/복귀 제한 초과 |
| RESTART | 새 문제 세트 시작을 위해 기존 attempt 포기 |

### Response 200

```json
{
  "success": true,
  "data": {
    "abandoned": true,
    "attemptId": "8c9d0e1f-...",
    "status": "ABANDONED",
    "energyRefunded": false
  }
}
```

### 구현 노트

```jsx
1. CHILD JWT 검증 후 childId 추출
2. attempt.child_id == childId 검증
3. IN_PROGRESS 상태만 ABANDONED로 변경 가능
4. 기본 정책: 일반 모드 시작 시 차감한 에너지는 환불하지 않음
5. 보상/진행도/스트릭/퀘스트/업적은 반영하지 않음
6. 이미 SUBMITTED/EXPIRED/ABANDONED면 409 ATTEMPT_ALREADY_CLOSED 반환
```

## 9. 구현 가이드

### Entity / DTO 기준

```java
class MissionSet {
    Long id;
    Mission mission;
    Integer starLevel;   // 1, 2, 3
    Integer variantNo;   // 동일 별 난이도의 후보 세트 번호
}

class MissionQuestionsResponse {
    Long setId;
    Long missionId;
    String missionCode;
    Integer starLevel;
    Integer variantNo;
    Boolean isReview;
    List<QuestionResponse> questions;
}
```

### Repository 기준

```java
List<MissionSet> findByMissionIdAndStarLevel(Long missionId, int starLevel);

List<MissionSetProgress> findByChildIdAndMissionIdAndStarLevel(
    Long childId,
    Long missionId,
    int starLevel
);
```

### 주의사항

- `levelNo`는 신규 API 응답과 요청에서 사용하지 않는다.
- `starLevel`은 반드시 1, 2, 3 중 하나여야 한다.
- `difficulty`는 개별 문항의 난이도(`LOW`, `MEDIUM`, `HIGH`)로만 사용한다.
- 클라이언트는 세트를 직접 고르지 않고 `missionId + starLevel`만 전달한다.
- 서버는 선택된 세트의 `setId`를 응답에 포함해 이후 채점/제출/리포트 API가 동일 세트를 기준으로 동작하도록 한다.
