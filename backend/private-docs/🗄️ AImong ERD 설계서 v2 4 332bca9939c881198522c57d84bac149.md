# 🆕 v2.4 핵심 변경 요약

- `setId`는 진행도, attempt, 복습, check/submit/report 연결을 위한 학습 단위 식별자로 유지한다.
- 실제 문항 선택 조건은 `question_bank.set_id`가 아니라 `missionId + difficulty` 후보 풀이다.
- 런타임에 선택된 문항 목록은 `quiz_attempts.question_ids_json`에 저장하고, check/submit/report 검증 기준으로 사용한다.
- `mission_answer_results.selected_answer TEXT`를 추가해 submit 시 사용자가 제출한 답과 report의 `submittedAnswer`를 저장/조회할 수 있게 한다.

```sql
ALTER TABLE mission_answer_results
  ADD COLUMN selected_answer TEXT;
```

# 🆕 v2.2 핵심 변경 요약

- 미션/퀴즈 출제의 정본 기준은 `mission_sets.set_id`로 확인한 `mission_id`, `star_level`, 난이도 비율 정책이다.
- `question_bank.set_id`는 운영/이관 호환용 메타데이터로 유지하되, 현재 출제 조건으로 사용하지 않는다.
- 출제는 `missionId + difficulty` 후보 풀에서 starLevel 난이도 비율에 맞춰 10문항을 런타임 랜덤 선택하는 방식이다.
- 문제은행 운영 풀은 총 1,056문항으로 통일한다. 실제 플레이 세트 기준으로 구성되는 문항 수는 96세트 x 10문항 = 960문항이며, 각 세트의 10문항은 세트 난이도 비율에 따라 문제은행에서 런타임 랜덤 선택한다. 추가 HIGH 96문항은 품질 보정/교체/운영 예비 풀로 관리한다.
- 1,056문항 운영 풀과 HIGH 96문항 추가 정책은 ERD 기준에 포함한다. 출제 시점에는 고정된 `setId`의 정책에 따라 LOW/MEDIUM/HIGH 비율을 맞춰 10문항을 런타임 선택한다.

# 🆕 v2.1 핵심 변경 요약

- `quiz_attempts.question_ids_json`은 문제 조회 시 런타임 선택된 10문항을 저장하고, `answered_question_ids_json`은 진행 중 attempt 복구 시 이미 check한 문항 목록을 저장한다.
- `mission_attempts`에 KST 날짜 집계와 제출 감사 기준인 `attempt_date`, `attempt_no`, `submitted_at`을 명시한다.
- `mission_daily_progress`는 일별 요약을 유지하되 부모 홈/주간 통계 계산에 필요한 `mission_id`, `first_attempt_at`, `best_score`, `total`, `first_xp_earned`, `total_xp_earned`, `review_attempt_count`를 구현 확장 컬럼으로 포함한다.
- check API는 `quiz_attempts`를 세션 검증 및 answered question 복구 상태 갱신에만 사용하고, 보상/진행도/통계 저장은 최종 submit에서만 처리한다.

```sql
-- 진행 중 attempt 복구 상태
ALTER TABLE quiz_attempts
  ADD COLUMN question_ids_json JSONB NOT NULL DEFAULT '[]'::jsonb,
  ADD COLUMN answered_question_ids_json JSONB NOT NULL DEFAULT '[]'::jsonb,
  ADD COLUMN remaining_lives SMALLINT NOT NULL DEFAULT 3 CHECK (remaining_lives BETWEEN 0 AND 3),
  ADD COLUMN wrong_count_in_session SMALLINT NOT NULL DEFAULT 0 CHECK (wrong_count_in_session >= 0),
  ADD COLUMN revive_count SMALLINT NOT NULL DEFAULT 0 CHECK (revive_count BETWEEN 0 AND 1),
  ADD COLUMN revived_at TIMESTAMPTZ;

-- KST 날짜 집계 / 시도 순번 / 제출 시각
ALTER TABLE mission_attempts
  ADD COLUMN attempt_date DATE NOT NULL,
  ADD COLUMN attempt_no INT NOT NULL,
  ADD COLUMN submitted_at TIMESTAMPTZ NOT NULL DEFAULT now();

-- 부모 홈/주간 통계와 홈 계산용 일별 요약 확장
ALTER TABLE mission_daily_progress
  ADD COLUMN mission_id UUID REFERENCES missions(id) ON DELETE SET NULL,
  ADD COLUMN first_attempt_at TIMESTAMPTZ NOT NULL,
  ADD COLUMN best_score INT NOT NULL DEFAULT 0 CHECK (best_score >= 0),
  ADD COLUMN total INT NOT NULL DEFAULT 10 CHECK (total > 0),
  ADD COLUMN first_xp_earned INT NOT NULL DEFAULT 0 CHECK (first_xp_earned >= 0),
  ADD COLUMN total_xp_earned INT NOT NULL DEFAULT 0 CHECK (total_xp_earned >= 0),
  ADD COLUMN review_attempt_count INT NOT NULL DEFAULT 0 CHECK (review_attempt_count >= 0);
```

# 🔑 핵심 설계 원칙

- **Supabase PostgreSQL** 기반, 모든 테이블에 RLS(Row Level Security) 적용
- **KST(UTC+9)** 기준으로 날짜 계산. 서버 타임존 `Asia/Seoul` 설정 필수
- **소프트 삭제 기본** — 부모/자녀 삭제 시 `deleted_at` 기록, FCM token 제거, 자녀 `code = NULL`, `session_version + 1`로 기존 세션 무효화. 물리 삭제는 관리자 정리 작업 또는 법적 삭제 완료 배치에서 수행
- **반올림 규칙**: 모든 XP 계산 결과는 Math.floor 적용
- **식별자 규칙**: 도메인 PK는 UUID v4를 기본으로 사용하되, `parent_accounts.parent_id`는 Firebase UID(TEXT)를 사용
- **정답은 `private` 스키마**에만 저장 — RLS + 스키마 분리 이중 보호
- **정오답 로그 분리**: `mission_answer_results`를 통해 문항 단위 통계와 부모 대시보드 `incorrectRate`를 계산

## 2-1. login_attempts (자녀 코드 로그인 실패 제한)

> Redis 대신 PostgreSQL에서 IP/CODE 기준 실패 횟수와 임시 잠금 상태를 관리한다. 실패한 code가 실제 자녀 프로필에 없을 수 있으므로 `child_profiles`에 저장하지 않는다.
> 

```sql
CREATE TABLE login_attempts (
  key             VARCHAR(255) PRIMARY KEY,       -- login:ip:{ip} 또는 login:code:{code}
  failure_count   INT NOT NULL DEFAULT 0 CHECK (failure_count >= 0),
  locked_until    TIMESTAMPTZ,
  expires_at      TIMESTAMPTZ NOT NULL
);

CREATE INDEX idx_login_attempts_expiry
  ON login_attempts(expires_at, locked_until);
```

- 로그인 전 IP/CODE key를 모두 확인하고, `locked_until > now()`이면 `429 TOO_MANY_REQUESTS`를 반환한다.
- 코드 조회 실패 시 IP/CODE 각각 실패 횟수를 증가시키고, 3회 이상이면 30초 잠금을 건다.
- 로그인 성공 시 관련 실패 row를 삭제하거나 초기화한다.
- 만료 row는 조회/갱신 시 무효 처리하고, 주기 cleanup으로 삭제할 수 있다.

```sql
CREATE TABLE missions (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),

CREATE TABLE mission_sets (

  star_level      SMALLINT NOT NULL CHECK (star_level BETWEEN 1 AND 3),

CREATE TABLE question_bank (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  mission_id       UUID REFERENCES missions(id) ON DELETE CASCADE,
  set_id           VARCHAR(32) REFERENCES mission_sets(set_id) ON DELETE SET NULL,
  question_type    question_type_enum NOT NULL,
  prompt           TEXT NOT NULL,
  options          JSONB,
  content_tags     JSONB NOT NULL DEFAULT '[]'::jsonb,
  curriculum_ref   TEXT NOT NULL,
  difficulty       question_difficulty_enum NOT NULL,
  source_type      question_source_enum NOT NULL DEFAULT 'STATIC',
  generation_phase question_generation_phase_enum NOT NULL DEFAULT 'PREGENERATED',
  question_pool_status question_pool_status_enum NOT NULL DEFAULT 'ACTIVE',
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  is_active        BOOLEAN NOT NULL DEFAULT TRUE
);

-- 비공개: 정답 + 해설 (private 스키마)
CREATE TABLE private.question_answer_keys (
  question_id     UUID PRIMARY KEY REFERENCES public.question_bank(id) ON DELETE CASCADE,
  answer_payload  JSONB NOT NULL,
  explanation     TEXT NOT NULL,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 클라이언트용 안전 뷰 (answer/explanation 제외)
CREATE VIEW public.question_bank_safe AS
  SELECT id, mission_id, set_id, question_type, prompt, options, content_tags, curriculum_ref, difficulty, source_type, generation_phase, created_at
  FROM public.question_bank
  WHERE is_active = TRUE
  AND question_pool_status = 'ACTIVE';
```

- 사용자 선택 난이도는 `star_level` 1, 2, 3만 허용한다.
- 동일 소단원/별 난이도마다 후보 세트 2개를 준비한다. 전체 세트는 `16미션 x 3난이도 x 2후보 = 96세트`다.
- 문항 난이도 `question_bank.difficulty`는 개별 문항 난이도이며 `LOW | MEDIUM | HIGH`만 허용한다.
- 별 난이도별 문항 구성은 별 1개 `7:2:1`, 별 2개 `3:5:2`, 별 3개 `2:3:5`다.
- 런타임 조회는 서버가 `mission_id + star_level` 후보 세트 중 미완료 세트 우선 랜덤 선택 후 `set_id` 기준 활성 문항 10개를 반환한다.
- `question_pool_status = QUARANTINED` 또는 `RETIRED`인 문항은 출제 풀에서 제외한다.

## 4-1. quiz_attempts (문제 세션 — API v1.1 신규)

```sql
-- GET /mission-sets/{setId}/questions 호출 시 생성
-- POST /mission-sets/{setId}/check 호출 시 세션 검증에 참조
-- POST /mission-sets/{setId}/submit 호출 시 최종 소비
CREATE TABLE quiz_attempts (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id            UUID NOT NULL REFERENCES child_profiles(child_id) ON DELETE CASCADE,
  mission_id          UUID NOT NULL REFERENCES missions(id) ON DELETE CASCADE,
  set_id              VARCHAR(32) NOT NULL REFERENCES mission_sets(set_id),
  star_level            SMALLINT NOT NULL CHECK (star_level BETWEEN 1 AND 3),
  question_ids_json   JSONB NOT NULL,                -- 배정된 문제 10개 UUID 배열
  status              attempt_status_enum NOT NULL DEFAULT 'IN_PROGRESS',
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  expires_at          TIMESTAMPTZ NOT NULL,          -- 권장 30분
  submitted_at        TIMESTAMPTZ,                   -- 최종 제출 시각
  abandoned_at        TIMESTAMPTZ,                   -- 사용자가 포기한 시각
  abandon_reason      VARCHAR(64),

  CHECK (submitted_at IS NULL OR submitted_at >= created_at),
  CHECK (abandoned_at IS NULL OR abandoned_at >= created_at),
  CHECK ((status = 'SUBMITTED') = (submitted_at IS NOT NULL)),
  CHECK ((status = 'ABANDONED') = (abandoned_at IS NOT NULL))
);

CREATE INDEX idx_quiz_attempts_child ON quiz_attempts(child_id, created_at DESC);
```

- check API는 소유자, missionId, questionId 포함 여부, `expires_at`, `status = IN_PROGRESS` 검증에만 참조한다.
- check API는 `status`, `submitted_at`을 변경하지 않으며, 최종 submit만 `status = SUBMITTED`, `submitted_at = now()`로 업데이트한다.
- `GET /api/mission-attempts/{attemptId}`는 `status = IN_PROGRESS`이고 `expires_at > now()`인 attempt만 복구 대상으로 반환한다.
- `POST /api/mission-attempts/{attemptId}/abandon`은 `status = ABANDONED`, `abandoned_at = now()`로 변경한다.

- 모든 톱니바퀴 증감은 `child_profiles.gear` 갱신과 같은 트랜잭션에서 원장에 기록한다.
- 하트 회복은 `amount = -HEART_REVIVE_GEAR_COST`, reason=`HEART_REVIVE`, ref_type=`QUIZ_ATTEMPT`, ref_id=`attemptId`로 기록한다.
- 스트릭 보호권 구매는 `amount = -STREAK_SHIELD_COST * count`, reason=`STREAK_SHIELD_PURCHASE`, ref_type=`STREAK_SHIELD`, ref_id는 요청 단위 식별자로 기록한다.

**friend_streaks 연결 트랜잭션 규칙**

- A가 B와 연결 시: `(A→B)`, `(B→A)` 두 행을 **하나의 트랜잭션**에서 동시에 insert
- `child_id PK` → A는 파트너 1명만 보유 가능 (DB 레벨 보장)
- `partner_child_id UNIQUE` → B도 동시에 다른 파트너를 가질 수 없음
- 파트너 탈퇴 시 → ON DELETE CASCADE로 두 행 자동 삭제

## 8. 티켓 / 가챠 / 조각

```sql
CREATE TABLE tickets (
  ticket_id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id     UUID NOT NULL REFERENCES child_profiles(child_id) ON DELETE CASCADE,
  ticket_type  ticket_type_enum NOT NULL,
  used_at      TIMESTAMPTZ,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_tickets_child_unused ON tickets(child_id, ticket_type) WHERE used_at IS NULL;

CREATE TABLE pet_fragments (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id     UUID NOT NULL REFERENCES child_profiles(child_id) ON DELETE CASCADE,
  grade        pet_grade_enum NOT NULL,
  count        INT NOT NULL DEFAULT 0 CHECK (count >= 0),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (child_id, grade)
);

CREATE TABLE gacha_pulls (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id        UUID NOT NULL REFERENCES child_profiles(child_id) ON DELETE CASCADE,
  ticket_type     ticket_type_enum NOT NULL,       -- NORMAL|RARE|EPIC
  result_pet_code TEXT NOT NULL,
  grade           pet_grade_enum NOT NULL,
  is_new          BOOLEAN NOT NULL,
  granted_pet_id  UUID,
  fragments_got   INT NOT NULL DEFAULT 0 CHECK (fragments_got >= 0),
  sr_miss_before  INT NOT NULL DEFAULT 0 CHECK (sr_miss_before >= 0),
  pulled_at       TIMESTAMPTZ NOT NULL DEFAULT now(),

  FOREIGN KEY (granted_pet_id, child_id) REFERENCES pets(id, child_id),
  CHECK (
    (is_new = TRUE AND granted_pet_id IS NOT NULL AND fragments_got = 0)
    OR (is_new = FALSE AND granted_pet_id IS NULL AND fragments_got > 0)
  )
);

CREATE INDEX idx_gacha_pulls_child ON gacha_pulls(child_id, pulled_at DESC);
```

| NORMAL | +1 | 10개 → 일반 1개 |
| RARE | +3 | 30개 → 희귀 1개 |
| EPIC | +8 | 80개 → 영웅 1개 |
| LEGEND | +20 | 200개 → 전설 1개 |

# 🔄 서비스 트랜잭션 권장 규칙

**\[학습 세트 제출 1회\]**

1. `quiz_attempts` FOR UPDATE 조회 및 `set_id` 일치 검증
2. `mission_attempts` insert (`set_id`, `star_level` 포함)
3. `mission_answer_results` insert (최종 submit의 문항별 정오답과 `selected_answer` 저장, `set_id` 포함, check 결과 제외)
4. 통과한 일반 모드일 때만 `mission_set_progress` upsert
5. 통과한 일반 모드일 때만 `mission_daily_progress` 일별 요약 및 부모 홈/주간 통계 계산용 확장 컬럼 upsert
6. `child_profiles` XP / last_active_at update
7. `pets` XP update 후 필요 시 진화 판정
8. `streak_records` update (`review=false`일 때만)
9. `daily_quest_progress` / `weekly_quest_progress` / `achievement_progress` / `milestone_rewards` / `streak_milestones` / `tickets` update (`review=false`일 때만)
10. `quiz_attempts.status = SUBMITTED`, `submitted_at` = now() 업데이트
11. commit

**\\\\\\\[문제 출제 1회\\\\\\\]**

1. 일반 학습 진입은 `mission_id + star_level`로 후보 세트를 조회하고 미완료 후보 우선 랜덤 선택
2. 복습 또는 직접 진입은 `mission_sets.set_id`로 세트 조회 및 잠금 검증
3. 일반 모드이면 `child_profiles`를 FOR UPDATE로 조회하고 에너지 회복분을 반영한 뒤 `energy >= 5` 검증
4. 복습 모드는 에너지 검증/차감 제외
5. `mission_sets.set_id`로 확인한 `mission_id`와 `star_level` 정책을 기준으로 `question_bank`의 `mission_id + difficulty` 활성 후보 풀 조회
6. 별 난이도 비율에 맞춰 안 푼 문제 우선 10문항 런타임 선택
7. 선택된 question_id 목록을 `quiz_attempts.question_ids_json`에 저장
8. `QuestionServingQualityGuard`로 serving 직전 재검증
9. 문제 부족 또는 검증 실패 시 `MISSION_SET_NOT_READY`
10. 일반 모드이면 `energy -= 5`, `energy_recovered_at` 갱신

**[가챠 1회]**

1. `tickets`에서 해당 타입 미사용 row 1건 차감 (`used_at` 갱신)
2. pity 계산 (`sr_miss_count` 기반)
3. 신규면 `pets` insert, 중복이면 `pet_fragments` upsert
4. `gacha_pulls` insert
5. `child_profiles.gacha_pull_count` / `sr_miss_count` update
6. commit

**[하트 회복 1회]**

1. `quiz_attempts` FOR UPDATE 조회 및 본인 attempt 검증
2. status=IN_PROGRESS, is_review=false, remaining_lives=0, revive_count=0 검증
3. `child_profiles` FOR UPDATE 조회 및 gear >= HEART_REVIVE_GEAR_COST 검증
4. `child_profiles.gear` 차감
5. `currency_transactions`에 HEART_REVIVE 기록
6. `quiz_attempts.remaining_lives=3`, `revive_count=1`, `revived_at=now()` 업데이트
7. commit

**[스트릭 보호권 구매]**

1. `child_profiles` FOR UPDATE 조회 및 gear >= STREAK_SHIELD_COST * count 검증
2. `child_profiles.gear` 차감
3. `child_profiles.shield_count += count`
4. `currency_transactions`에 STREAK_SHIELD_PURCHASE 기록
5. commit

**[공동 스트릭 연결]**

1. `friend_streaks` A→B insert
2. `friend_streaks` B→A insert
3. commit (둘 다 성공해야 커밋)

> - `quiz_attempts.answered_question_ids_json`을 추가해 진행 중 attempt 복구 상태를 저장하도록 반영
> 

> - `mission_attempts.attempt_date`, `attempt_no`, `submitted_at`을 추가해 KST 날짜 집계와 제출 감사 기준을 명시
> 

> - `mission_daily_progress`에 부모 홈/주간 통계 계산용 확장 컬럼을 반영
> 

> **v1.6 → v1.7 변경 이력**:
> 

> - `missions`를 교육 주제, `mission_sets`를 96개 고정 학습 세트로 분리
> 

> - `question_bank`, `quiz_attempts`, `mission_attempts`, `mission_answer_results`에 `set_id` 기준을 추가
> 

> - `mission_set_progress`를 추가해 자녀별 세트 완료를 영속 기록하고, `mission_daily_progress`는 일별 요약으로 역할 재정의
> 

> - 숫자 난이도/`difficulty_band`는 신규 명세에서 제거하고 `LOW | MEDIUM | HIGH` enum만 외부 계약으로 유지
>
